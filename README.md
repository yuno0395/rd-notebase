# rd-notebase

開発ノート(BtoB のものづくりの知見を、Obsidian と Box でためて使う仕組み)の正本です。
ここを直して版を出し、Box の共有 `_仕組み/tools/配布/<版>/` から各自の vault に当てます(`docs/00_仕様書.md`「仕組みの正本と配布」)。

## 中身

| 場所 | 中身 |
| --- | --- |
| `docs/` | 仕様書3点。`00_現場向け1枚.md`(現場の全員)、`00_仕様書.md`(まとめ役)、`00_同期プログラム要件.md`(プログラムを作る人)。`マニュアル/` は立場別(チームメンバー・PL・システム管理者)の初期設定と普段の仕事、全員向けの K-Plex の使い方(絵は `マニュアル/img/`、`tools/make_kplex_figs.py` で作る)。共有 vault の `00_マニュアル/` に写す |
| `vault/共有/` | 共有 vault のひな形。テンプレートの正本 `_仕組み/templates/` と、配る Obsidian の設定 `_仕組み/設定/` もここ |
| `vault/個人/` | 個人 vault のひな形。テンプレートは組み立てるときに共有から写す |
| `vault/機密/` | 機密フォルダのひな形(事実と原本だけを置く) |
| `manifest.toml` | 配布の目録。どのファイルを上書きし、どれを最初だけ置くか |
| `tools/build.py` | 配布物を組み立てる |
| `tools/setup.py`・`tools/システム管理者.bat` | 準備と版の更新を bat 1つで行う中身(仕様書「bat 1つで準備と更新」)。PL・メンバーの bat は `vault/共有/_仕組み/tools/準備/` |
| `docs/old/` | 2026-10-22 に白紙に戻す前の検討と、v0.4 の草案 |

昔の試作のコードはブランチ `archive/prototype-1` にあります。

このリポジトリは public です。入れてよいのは仕組みと作り物の見本だけです。実際のノート・顧客の資料・社内の名前や PC のパスは入れません(仕様書「社外へ出さない・関係ないファイルを書き換えない」)。

## 版を出す

ふつうは `tools\システム管理者.bat` を押して「新しい版を出して配る」を選ぶだけです(テスト・組み立て・プラグイン・Box に置く・共有 vault に当てる・タグまで)。各自は共有 vault の `_仕組み/tools/準備/` の bat を押して当てます。下は bat が中でしていることです。

1. 直したら、`docs/00_仕様書.md` の変更履歴に書く。
2. `python tools/build.py 0.1.0`(Python 3.11 以上)で `dist/0.1.0/` を作る。目録にないファイルがあると止まる。
3. `python tools/plugins.py pack 0.1.0 --from <プラグインを入れた設定フォルダ>` で `dist/0.1.0/プラグイン/` にプラグインの本体・LICENSE・AGPL/GPL のソース zip・出典一覧をそろえる(ネットを使う。本体はリポジトリに入れない)。
4. `dist/0.1.0/` を Box の共有 `_仕組み/tools/配布/0.1.0/` に置き、GitHub に同じ名前のタグをつける。各自は `プラグインを入れる.bat` でプラグインを入れる。
5. 同期プログラムができるまでは、各 vault に手で当てる。`manifest.toml` の system は上書きし、seed はないときだけ置く。ノートには触れない。
