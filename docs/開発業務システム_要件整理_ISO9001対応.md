# 開発業務システム 要件整理（ISO 9001対応）

研究開発・量産を行うメーカー向け基幹システムのうち、**開発業務の効率化**を目的とした第1段階の要件整理。

- 準拠規格：ISO 9001:2026（2026年9月16日発行）／JIS Q 9001:2026（2026年12月発行予定）
- 箇条番号は2015年版基準で記載。新規格の規格票で最終照合すること
- 設計原則：**業務をこなすと記録が自動で残る**。ゲート条件・承認権限をシステムで強制し、監査時は抽出するだけで証跡がそろう状態を目指す

---

## 1. 開発業務と必要機能

### 1.1 企画・要求定義

**業務**
- 顧客・市場要求の収集、製品企画、要求仕様書の作成、ロードマップ策定

**機能（基本）**
- 顧客要求（VoC）の登録と、仕様・設計項目・試験へのトレーサビリティ紐付け
- 要求仕様のバージョン管理と承認フロー
- 製品・技術ロードマップ管理

**機能（ISO 9001対応で追加）**

| 対応箇条 | 要求の趣旨 | システム機能 |
|---|---|---|
| 4.2 利害関係者のニーズ | 顧客以外（規制当局、社内製造・サービス部門等）の要求も把握 | 要求の**出所区分**（顧客／法規／社内／市場）を必須項目化 |
| 8.2.1 顧客とのコミュニケーション | 製品情報の提供、引合い・契約・変更の取扱い、顧客フィードバック | 顧客とのやり取り（打合せ記録、仕様回答、苦情）を要求に紐付けて記録 |
| 8.2.2 要求事項の明確化 | 適用法令・規制要求、組織が必要とする要求を明確化 | **適用法令・規格のチェックリスト**（安全、環境、含有物質、輸出管理等）を要求定義時に必須入力 |
| 8.2.3 要求事項のレビュー | 提供前に要求を満たせるかレビューし、結果と新たな要求を記録 | **要求仕様レビュー（受注前／開発着手前）ワークフロー**、レビュー結果・指摘・承認者を記録 |
| 8.2.3 （明示されない要求） | 顧客が明示しないが用途上必要な要求も含める | 「暗黙要求」区分の登録、過去案件テンプレートからの補完提案 |
| 8.2.4 要求事項の変更 | 変更時は関連文書を改訂し、関係者に周知 | 要求変更時の**影響先（仕様・設計・試験）自動抽出と通知**、変更履歴 |
| 8.3.2 j) 顧客・ユーザーの参画 | 設計プロセスへの顧客参画の必要性を考慮 | 顧客承認・顧客立会いの要否を要求ごとに設定 |
| 8.3.3 インプット | 機能・性能、過去の類似設計、法令規制、標準・規範、**失敗した場合の潜在的な結果** | 要求ごとに「未達時の影響度」を記録しFMEAへ連携、類似案件・過去不具合の参照記録 |
| 8.3.3 （インプットの品質） | 目的に対して適切、完全、曖昧でないこと。矛盾は解決すること | **要求品質チェック**（定量化されているか、検証方法があるか、重複・矛盾がないか）、矛盾要求の解決記録 |
| 8.5.5 引渡し後の活動 | 保守、保証、サービス、廃棄・リサイクル等の要求 | ライフサイクル要求（保守性、保証期間、部品供給年限、廃棄）の区分を用意 |
| 6.1 リスクと機会 | リスクと機会を決定し対応 | 要求ごとに技術リスク・事業リスクを登録し、リスク登録簿へ連携 |
| 7.1.6 組織の知識 | 必要な知識を明確にし維持・利用可能にする | 過去の要求仕様・教訓（Lessons Learned）をナレッジとして検索・再利用 |

**要求1件あたりの必須属性（データ項目）**

| 項目 | 内容 | 主な根拠 |
|---|---|---|
| 要求ID | 一意の識別番号 | 8.5.2 / 7.5 |
| 要求文 | 定量的・検証可能な記述 | 8.3.3 |
| 出所区分 | 顧客／法規・規格／社内／市場／暗黙 | 4.2 / 8.2.2 |
| 出所詳細 | 顧客名、規格番号、文書・議事録へのリンク | 8.2.1 |
| 分類 | 機能／性能／安全／環境／信頼性／保守性／コスト／ライフサイクル | 8.3.3 / 8.5.5 |
| 優先度 | 必須／重要／希望 | 8.2.3 |
| 合否判定基準 | 数値・条件で記述 | 8.3.3 / 8.3.5 |
| 検証方法 | 試験／解析／検査／レビュー（デモンストレーション） | 8.3.4 |
| 妥当性確認の要否 | 実使用条件での確認が必要か | 8.3.4 |
| 未達時の影響度 | 安全・顧客・法規への影響（FMEA連携） | 8.3.3 / 6.1 |
| 関連リスク | リスク登録簿へのリンク | 6.1 |
| トレースリンク | 上位要求、仕様、設計項目、図面、試験 | 8.3.4 / 8.5.2 |
| 状態 | 起案／レビュー中／承認／変更中／検証済／廃止 | 7.5 |
| 版・変更履歴 | 版番号、変更理由、変更者、日時 | 7.5 / 8.2.4 |
| 承認者・承認日 | 権限を持つ者による承認 | 7.5 / 7.2 |
| 顧客承認の要否 | 顧客合意が必要か、合意記録 | 8.3.2 j) |

### 1.2 プロジェクト管理

**業務**
- 日程計画、工数・予算管理、デザインレビュー（DR）やフェーズゲートの判定

**機能**
- WBS／ガント、マイルストーン管理
- 人別・案件別の工数集計と予実管理
- ゲート判定ワークフロー（判定基準のチェックリスト、承認記録）
- 【ISO 8.3.2】プロジェクト作成時にゲート構成・レビュー／検証／妥当性確認の時期・責任者の設定を必須化

### 1.3 設計（構想〜詳細）

**業務**
- 構想設計、3D CAD／図面作成、部品選定、E-BOM作成、出図

**機能**
- PDM（CADデータ・図面の版管理、チェックイン／アウト）
- E-BOMの構成管理
- 部品DB（標準品・推奨品の提示、類似部品・流用設計の検索）
- 出図承認ワークフロー
- 【ISO 8.3.5】アウトプットとインプット要求の対応確認

### 1.4 解析・設計品質

**業務**
- CAE解析、公差解析、FMEA、DR指摘の対応

**機能**
- 解析条件・結果の管理（モデルと版の紐付け）
- FMEAテンプレートと過去不具合DBの自動参照
- DR指摘事項の登録・期限・クローズ管理

### 1.5 試作・評価

**業務**
- 試作手配、試験計画、実験・評価、不具合対応

**機能**
- 試作部品の発注・進捗管理
- 試験計画と結果（生データ含む）の一元管理、要求仕様との合否紐付け
- 不具合トラッキング（原因・対策・再発防止の記録）
- 【ISO 8.3.4】要求↔試験結果の合否マトリクス、未完了項目があるとゲート通過不可
- 【ISO 7.1.5】使用計測器の校正期限チェック（期限切れなら記録不可）

### 1.6 設計変更管理

**業務**
- 変更要求（ECR）、変更指示（ECO）、影響評価

**機能**
- ECR→ECOのワークフロー
- 使用先展開（Where-used）による影響範囲の自動抽出
- 在庫・仕掛・発注残への影響表示、切替時期の管理
- 【ISO 8.3.6】変更の識別・レビュー・承認・悪影響防止策の記録

### 1.7 原価・調達

**業務**
- 目標原価設定、見積取得、サプライヤー選定

**機能**
- BOMからのコスト積み上げと目標原価との差分表示
- 見積依頼・回答管理（サプライヤーポータル）
- 部品の供給リスク（EOL・リードタイム）管理
- 【ISO 8.4】サプライヤー評価・選定記録、外注設計の管理

### 1.8 量産移行

**業務**
- E-BOM→M-BOM変換、工程設計、量産試作、製造・品証への引き渡し

**機能**
- E-BOM／M-BOMの差分管理と変換
- QC工程表・作業標準との連携
- 量産移管チェックリストと承認

### 1.9 規格・法規・認証

**業務**
- 安全規格（SEMI S2、CE等）対応、含有化学物質（RoHS、REACH）管理

**機能**
- 製品ごとの適用規格と適合証跡の管理
- 部品単位の含有物質データ集計

### 1.10 技術ナレッジ・知財

**業務**
- 技術報告書作成、ノウハウ蓄積、特許調査・出願

**機能**
- 報告書・議事録・不具合記録を横断検索（AIによる要約・類似事例提示）
- 発明提案の登録と出願状況管理
- 【ISO 7.1.6】組織の知識としての維持・アクセス管理

### 1.11 市場品質フィードバック

**業務**
- フィールド不具合の分析、次期設計への反映

**機能**
- フィールド不具合を該当部品・図面・要求に紐付けて設計側へ戻すループ
- 不具合傾向の分析ダッシュボード

## 3. 進め方

### 3.1 コアデータモデル
全領域の土台となる4つのデータを先に固める。

- **品目・BOM**
- **文書**（要求仕様、図面、仕様書、報告書）
- **変更**（ECR／ECO、要求変更）
- **課題**（DR指摘、不具合、是正処置）

### 3.2 MVPの優先順位
1. 要求管理（1.1）＋文書の版管理・電子承認（7.5）
2. PDM＋BOM管理
3. 設計変更管理
4. 課題・不具合トラッキング（CAPA含む）

要求管理を起点にトレーサビリティをつなげることで、顧客要求に紐づかない開発を構造的に防ぎ、ISO 8.2／8.3の証跡も同時にそろえる。
