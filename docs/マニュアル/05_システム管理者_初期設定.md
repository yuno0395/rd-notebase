# システム管理者 初期設定

> 正本は rd-notebase の `docs/マニュアル/`。仕様書 v0.53・要件書 v0.27 に合わせています。

システム管理者は、仕組みの面倒を見る人です。Box のフォルダと権限、配布物、同期プログラムを受け持ちます。ノートの中身や優先順位は PL の仕事なので、ここでは扱いません。

チームを始めるときに1回だけやることを、順番に書きます。

## 0. 用意するもの

| もの | 使いみち |
| --- | --- |
| Box の管理者か、フォルダを作って共同作業者を決められる権限 | フォルダと権限 |
| 自分の Windows PC に Python 3.11 以上 | 配布物の組み立てと、同期プログラム(exe になるまで)。なければ bat が入れる |
| GitHub の rd-notebase を読めること | 仕組みの正本。全員が GitHub を使う必要はない(配布は Box で行う) |
| Git | 正本を手元に持つ。置き場所は Box の外(例: `C:\dev\rd-notebase`)。Box の中に置くと .git が壊れることがある。なければ bat が入れる |

## bat で始める

下の 1〜4 と 7 は、`システム管理者.bat` を1回押せば済みます。

1. Box Drive を入れてサインインします。
2. GitHub の rd-notebase の「Code → Download ZIP」を、Box の外(例: `C:\dev`)に展開し、`tools\システム管理者.bat` をダブルクリックします。Python と Git がなければ入れます(自分のユーザーだけ。管理者の権限はいりません)。
3. 「正本を C:\dev\rd-notebase に置きました」と出たら、これからは `C:\dev\rd-notebase\tools\システム管理者.bat` を押します。もう一度押します。
4. 聞かれたことに答えます。

| 聞かれること | 答え方 |
| --- | --- |
| Box Drive のフォルダ | Enter(ふつうは `C:\Users\<ユーザー名>\Box`) |
| 共有 vault・開発データ・報告フォルダの場所 | Enter で下の 1 の例の場所。なければ作る |
| 出す版の番号 | Enter(次の番号が出ている) |
| あなたはどれですか | メンバー.csv から自分を選ぶか「自分を新しく登録する」 |
| この PC の記号・個人 vault の場所 | Enter |

5. 正本の中で版を組み立て(自動テストが落ちたら、ここで止まって何も配りません)、「これからすること」が出ます。読んで Enter を押します。
6. 最後に出る「手でやること」をします(Box での招待、Templater のスイッチ、設定フォルダの上書きなど)。
7. 下の 3 の 2(チーム設定)と、上司への案内(下の 9)をします。

- 2回目からは、同じ bat で「新しい版を出して配る」「メンバーを足す」「自分の環境だけ整える」を選べます([[06_システム管理者_普段の仕事]])。
- 押すたびに、前回までの控え(`%APPDATA%\知見同期\準備の控え\`)を残すか捨てるか聞かれます。Enter なら、前回が最後まで終わっていれば捨て、途中で止まっていれば残します。
- 先に何が起きるか見たいときは、コマンドプロンプトで `システム管理者.bat 試し` と打ちます(何も変えません)。
- 機密フォルダは、案件ごとに PL が `プロジェクトリーダー.bat` で用意します(下の 5 は bat を使わないときの手順)。

下の 1〜8 は、bat が中でしていることと、bat が使えないときの手順です。

## 1. Box にフォルダを作る

3種類のフォルダは入れ子にせず、別々の場所に作ります。権限は各フォルダに直接つけます。

| フォルダ | 例 | 共同作業者 |
| --- | --- | --- |
| 共有 vault | `Box\チーム\開発ノート_共有\` | チーム全員(編集) |
| 開発データ(重い添付) | `Box\チーム\開発データ\` | チーム全員(編集) |
| 管理者向け報告 | `Box\チーム\開発ノート_報告\` | チーム全員(編集)と、週報を読む上司(閲覧) |
| 個人 vault | `Box\個人\開発ノート_<名前>\` | なし(本人だけ。各自が作る) |
| 機密フォルダ | `Box\機密\顧客A\`(名前は自由) | その案件の担当者だけ。権限がない人にはフォルダがあることも見えない |

## 2. 配布物を組み立てる

1. 正本を手元に持ってきます。

```
git clone https://github.com/yuno0395/rd-notebase.git C:\dev\rd-notebase
cd C:\dev\rd-notebase
```

2. 版の番号を決めて組み立てます(例: 0.2.0)。目録(`manifest.toml`)にないファイルがあると止まります。

```
python tools\build.py 0.2.0
```

3. できた `dist\0.2.0\`(`共有` `個人` `機密` と `manifest.toml`)を、Box の共有 vault の `_仕組み/tools/配布/0.2.0/` に置きます。共有 vault がまだ空なら、先に 3 をしてから置きます。
4. GitHub に同じ名前のタグ(`v0.2.0` など)をつけます。

## 3. 共有 vault を作る

1. `dist\0.2.0\共有\` の中身を、すべて共有 vault のフォルダへコピーします。仕様書の写し・マニュアル(`00_マニュアル/`)・テンプレート・一覧・配る Obsidian の設定が入ります。
2. チーム設定 `_仕組み/同期設定.yaml` を直します。

```yaml
report_sections:             # 週報に載せる節。false で外す
  今週のトピック: true       # 台帳に選んだノートと手書きのダイジェスト
  開発の目処: true           # 成果物候補ごとの、方針リスクの解決数と未解決数
  候補の数: true
  マイルストーン: true
  中途半端な仕事: true       # priority 3・4 なのに一部だけ進めたイシュー
  担当者: true
  出荷準備度: false          # 開発の後の方で true にする
  同じノード: false          # プロジェクトが2つ以上になったら 自動(2つ以上のときだけ載る)にする
```

- v0.55 までの節(見込み・成果物候補・目的に沿わない・反論のついた仮説・行き詰まり・機密)は v0.56 で外しました。古い設定に残っていても無視されます。
- `member_code_length` の行は v0.43 で外しました(人の部分はいつも4文字)。古い設定に残っていても無視されます。
- 同期設定.yaml が YAML として読めなくなると、全員の同期が止まります。直したら、自分の PC で `notesync once --dry-run` を1回通してから保存し直してください。

## 4. メンバーを登録する

共有 vault の `_仕組み/tools/同期プログラム/メンバー.csv` に、1人1行で書きます。

```
名前,番号,使い始めた日
Yu,229999,2026-10-24
佐藤,123456,2026-10-27
```

- 番号は6桁の数字(社員番号など)。id の後ろ4文字は、これを36進数にしたものです(229999 → `4XGV`)。
- ほかの人と重ならないことを確かめます。重なると、同じ id ができて共有に集まらなくなります。
- 前から使っている3文字の記号(例: `001`)は、そのまま使えます。その人のノートの id も直しません。
- 名前は、各自の `個人設定.md` の name、同期プログラムの config.yaml の member、台帳の members と、すべて同じ書き方にします。
- メンバーを共有 vault・開発データ・報告フォルダの共同作業者に招待します。

## 5. 機密フォルダを作る(顧客の資料を扱うときだけ)

1. Box に機密フォルダを作り、共同作業者をその案件の担当者だけにします。
2. `dist\0.2.0\機密\` の中身をコピーします。
3. `00_README.md` に、中身・見てよい人・共有の窓口ノートの名前(例: 案件A)を書きます。顧客名はこの README と事実ノートにだけ書いてかまいません。
4. PL か案件の担当に、共有 vault で「機密の窓口」ノートを作ってもらいます(PL 初期設定の 6)。
5. 機密 vault を Obsidian で開く人は、設定フォルダを `.obsidian-<自分の6桁の番号>_<PCの記号>`(例: `.obsidian-229999_aa11234567`)にし、`_仕組み/設定/.obsidian` の中身をコピーします。`_仕組み/tools/メンバー.csv` に自分がいるか確かめます(共有のメンバー.csv の写し)。

## 6. 各メンバーの PC を用意する

メンバーが [[01_チームメンバー_初期設定]] を進めるのを手伝います。とくに次の3つは、つまずきやすいので一緒に確かめます。

- 配布物の `個人` を、隠しフォルダ `.obsidian` ごとコピーしたか
- `_仕組み/個人設定.md` の number を引用符で囲み、メンバー.csv と同じにしたか
- Templater の「Trigger Templater on new file creation」をオンにしたか

## 7. 同期プログラムを入れる

同期プログラム(notesync)は、各メンバーの PC で1つずつ動かします。exe にまとめるまでは Python で動かします。

**入れる**

1. Python 3.11 以上を python.org から入れます。入れるときに「Add python.exe to PATH」にチェックします。
2. 正本を PC の Box の外に置きます。Git があれば `git clone https://github.com/yuno0395/rd-notebase.git C:\dev\rd-notebase`、なければ GitHub の「Code → Download ZIP」を `C:\dev\rd-notebase` に展開します。
3. `C:\dev\rd-notebase\sync\起動\0_準備.bat` をダブルクリックします。yaml を読む部品(pyyaml)を入れ、`%APPDATA%\知見同期\config.yaml` にひな形を置いて、メモ帳で開きます。

コマンドで使いたい人は、代わりに `pip install -e C:\dev\rd-notebase\sync` で `notesync` コマンドを入れてもかまいません(`python -m notesync` と同じ)。

**起動用の bat**(`sync\起動\`。どれもダブルクリックで動き、終わると画面が止まって結果が読めます)

| bat | すること |
| --- | --- |
| `0_準備.bat` | 部品を入れ、config.yaml がなければひな形を置いてメモ帳で開く。何度押してもよい |
| `1_試し運転.bat` | `notesync once --dry-run`。ノートは何も変えず、個人 vault の `_仕組み/同期レポート.md` に予定だけを書く |
| `2_1回同期.bat` | `notesync once`。1回だけ同期する。config.yaml が `dry_run: true` のままなら、これも試し運転になる |
| `3_同期を続ける.bat` | `notesync watch --interval 3`。画面を開いている間だけ3分ごとに同期し、Ctrl+Shift+S にもすぐ応える。閉じるか Ctrl+C で止まる |
| `4_週報を作る.bat` | `notesync weekly`。今週の週報を作り直す(`report` を書いた PC だけ) |

よく使う `3_同期を続ける.bat` は、右クリック →「ショートカットの作成」でデスクトップに置いておくと楽です。bat は Box の中に置かないでください(正本の中で使います)。

**設定を書く**: `%APPDATA%\知見同期\config.yaml`(Box には置かない)を、自分の名前と Box の場所に直します。ひな形は `sync\config.example.yaml` です。

```yaml
member: 佐藤                                        # メンバー.csv と同じ名前
personal: C:\Users\sato\Box\個人\開発ノート_佐藤
shared: C:\Users\sato\Box\チーム\開発ノート_共有
shared_data: C:\Users\sato\Box\チーム\開発データ
report: C:\Users\sato\Box\チーム\開発ノート_報告      # 週報を作る PC だけ使う
secret:                                             # この PC で権限のある機密フォルダだけ
  - C:\Users\sato\Box\機密\顧客A
dry_run: true                                       # 最初は試し運転
idle_seconds: 10
```

- Box Drive の場所は、エクスプローラーで Box のフォルダを開き、アドレス欄をクリックして写すと間違えません。
- 機密フォルダがない人は `secret:` の下の行を消します。書いた機密フォルダが見つからないと、同期は止まります。

**試す**

1. `1_試し運転.bat` を押します(`notesync once --dry-run`)。画面に「試し運転しました(何も変えていません)」と、同期レポートの場所が出ます。
2. 同期レポートを開き、意図しない名前の変更や集約がないか確かめます。「止めました: 人の記号が食い違っています」などと出たら、下の表で直します。
3. よければ config.yaml の `dry_run` を `false` にして保存し、`2_1回同期.bat` で1回本番を動かします。画面に「同期しました」と出ます(「試し運転しました」と出たら、`dry_run` がまだ `true` です)。共有 vault の `<プロジェクト名>/` にノートが集まり、個人 vault の `90_共有/` に他の人のノートが届くか確かめます。
4. 仮運用で共有 vault に直接書かれたノートがあれば、`notesync recover`(試し運転)→ 確かめて `notesync recover --run` で、id のないノートに id をつけ、重い添付を `開発データ/` へ移します。

**手で動かし続ける**: `3_同期を続ける.bat` を押し、画面を開いたままにします。3分ごとに同期し、Obsidian の Ctrl+Shift+S(今すぐ共有へ)にもすぐ応えます。

- Ctrl+Shift+S は、この画面が開いている間だけ効きます。閉じていると、30秒後に右上に「同期プログラムから返事がありません」と出ます。困るのはそれだけで、ノートは消えません。次に bat を押したときに送られます。
- 止めるときは、画面を閉じるか Ctrl+C を押します。同期の途中で閉じても、次の回で続きからやり直します(書き換える前の元は backup に残ります)。
- PC を再起動したら、もう一度押します。

**常に動かす(常駐にするとき)**: 手で動かして困らなければ、サインイン時に自動で立ち上げます。Windows の「タスク スケジューラ」で基本タスクを作ります。手で試している間は登録しません。

| 項目 | 値 |
| --- | --- |
| トリガー | ログオン時 |
| 操作 | プログラムの開始。プログラムは `C:\dev\rd-notebase\sync\起動\3_同期を続ける.bat` |
| 条件 | 「AC 電源のときだけ」のチェックを外す |

週報は、config.yaml に `report` を書いた PC ならどれでも、月曜の最初の同期のときに作られます(最初の1台が作り、ほかの PC は作りません)。今すぐ作りたいときは `notesync weekly` です。

**起きたときの直し方**

| 出たこと | 直し方 |
| --- | --- |
| 人の記号が食い違っています | 個人設定.md の number とメンバー.csv の番号をそろえる |
| 個人設定.md の name が member と違います | 個人設定.md の name と config.yaml の member をそろえる |
| 人の記号がありません | 個人設定.md に number を書く |
| 個人設定に shared(shared_data・report)を書いてください | config.yaml に足す |
| 同じ id の警告 | 2人が同じ番号を使っていないかメンバー.csv を見る |

## 8. 本番の Box で手で動かして確かめる

常駐にする前に、本番の Box で、同期プログラムを手で起動して一通り確かめます。試しの場所(`Desktop\Box_試し` など)で使った config.yaml や bat は使わず、本番の場所で書き直します。

**そろえるもの**(1〜5 と、各メンバーの [[01_チームメンバー_初期設定]])

- [ ] 共有 vault・開発データ・報告フォルダ・機密フォルダが Box にあり、権限が 1 の表のとおり
- [ ] 共有 vault の `_仕組み/記録/版.txt` が、置いた配布物の版と同じ
- [ ] メンバー.csv に試す人が全員いる
- [ ] 試す人の個人 vault が Box にあり、`_仕組み/個人設定.md` の name・number がメンバー.csv と同じ
- [ ] 試す人の PC で `0_準備.bat` を押し、config.yaml を本番の場所に直した(`dry_run: true`)

**順番**

1. 全員が `1_試し運転.bat`。同期レポートに「止めました」がなく、予定の中身がおかしくないこと。
2. 1人ずつ `dry_run: false` にして `2_1回同期.bat`。1人目の個人 vault のノートが共有の `<プロジェクト名>/` に入ること。
3. 2人目が `2_1回同期.bat`。1人目のノートが2人目の `90_共有/` に届くこと。
4. 全員が `3_同期を続ける.bat` を開いたままにして、ふだんどおりノートを書きます。数分で共有に入ること、Ctrl+Shift+S で右上に「共有へ送りました」と出ること。
5. 機密の担当者は、個人 vault の試しのノートに機密フォルダの中の事実ノートへのリンクを書いて Ctrl+Shift+S。そのノートは共有に入らず、同期レポートに「機密へのリンク: …(共有していません)」と出ること(確かめたら、そのノートは消します)。
6. 週報を作る PC で `4_週報を作る.bat`。報告フォルダの `週報の一覧.html` がブラウザで開けること。
7. 1台で `3_同期を続ける.bat` を閉じ、Ctrl+Shift+S を押して「返事がありません」と出ること。もう一度開けば送られること。

**うまくいかないとき**: bat の画面に出た1行と、同期レポートのいちばん上を控えて、7 の「起きたときの直し方」を見ます。わからなければ、書き換える前の元が `%APPDATA%\知見同期\backup\` に30日残るので、そこから戻せます。

## 9. 終わったら

- PL に、共有 vault・メンバー登録・同期プログラムの状態を伝えます(どの PC で動いているか、仮運用かどうか)。
- 上司に、`開発ノート_報告/週報の一覧.html` をブラウザで開けば週報が読めることを伝えます。
- 保守のための控え(保守手順書・ソースの Git バンドル・テスト用 vault)を、共有 vault の `_仕組み/tools/同期プログラム/` に置きます。ソースの控えは `git bundle create rd-notebase.bundle --all` で1ファイルにできます。
