# チームメンバー 普段の仕事

> 正本は rd-notebase の `docs/マニュアル/`。仕様書 v0.42 に合わせています。手元に置く要約は `00_現場向け1枚.md`。

属性欄(ノートの先頭の `---` で囲まれた所)は、ほとんど手で書かなくて大丈夫です。キーで作れば、つながりや id は自動で入ります。

## ノートのつながり

仕事は一本の流れでつながっています。自分の仕事がどこにいるかがわかれば、何を書けばよいかもわかります。

```
価値の軸:   目的 ← 価値の仮説(何を満たすか)
                      ▲ 実現する(価値仮説)
成果物の軸: 目的 ← 成果物候補 ← 部分の案 ← イシュー ← タスク ← ナレッジ
                                      (どれからも、物や値の名前の「ノード」へリンクする)
```

| 種類 | 中身 | 名前の付け方の例 |
| --- | --- | --- |
| 目的 | 何のために、誰に何を届けるか(PL が置く) | 外観不良ゼロで樹脂カバーを量産する |
| 価値の仮説 | 目的を確かめられる形にしたもの | 電池が3年もつ |
| 設計案 | 目的を果たす成果物の候補と、その部分の案。実現する仮説を 価値仮説 でつなぐ。複数並べて磨き、絞る | A案 クランプ式 / 電池ユニット |
| イシュー | 候補が本当に仮説を実現できるかを脅かす心配 | 肉厚部のヒケで外観不良になるおそれ |
| タスク | イシューのリスクを減らす、半日以上の仕事 | 保圧を変えて試作する |
| ナレッジ | タスクの結果、リスクがどう変わったか | (タスクから作る) |
| ノード | 物や値の名前。辞書 | PA66、保圧、ヒケ量 |

## よく使うキー

選んだ文字か、何も選ばなければカーソルの行の文がノートの名前になり、元の行はそのノートへのリンクに変わります。作ったノートは開きません。そのまま書き続けてください。

| キー | すること |
| --- | --- |
| Ctrl+L | 行をチェックボックス `- [ ]` にする。もう一度押すと完了 |
| Ctrl+K | 選んだ語をノードにつなぐ。なければその場で作る。何も選ばずに押すと、名前と別名でノードを探せる |
| Ctrl+I | イシューにする |
| Ctrl+T | タスクにする(期日は1週間後で入る) |
| Ctrl+H | 価値の仮説にする |
| Ctrl+U | 設計案にする(目的で押すと成果物候補、候補の中で押すとその部分の案) |
| Ctrl+N | 種類を選んで新しいノートを作る(議事録・実験・試作記録などもここから) |
| Ctrl+S | 保存する。まだファイルのない `[[ ]]` があれば右上に名前が出る |
| Ctrl+Shift+S | 今すぐ共有へ。保存して、すぐ共有 vault へ送る(ふだんは数分ごと)。ノートの上の帯のボタンでもよい。同期プログラムが動いている間だけ効く(手で動かす間は `3_同期を続ける.bat` の画面を開いておく) |
| Ctrl+D | このノートの図を開く。なければ作り、カーソルの位置に引用を入れる |
| Ctrl+G | 今のノートを中心に K-Plex(つながりの図)を開く。見方は [[07_K-Plexの使い方]] |
| Ctrl+Shift+N | K-Plex の中心のノートから、イシュー・タスク・仮説・設計案を作る |

- キーを忘れたら、本文を右クリックしてメニューから選べます。目的とナレッジはメニューからだけ作ります。
- `[[ ]]` を打つだけではファイルはできません。あとで `[[ ]]` の中にカーソルを置き、種類に合わせて Ctrl+K / I / T / H / U を押せばその種類で作れます。
- Obsidian 標準の Ctrl+I(斜体)・Ctrl+T(新しいタブ)・Ctrl+H(置換)は使えません。斜体は `*文字*`、新しいタブは Ctrl+クリックで代わりになります。
- 自分でキー(設定 → ホットキー)や右クリックメニュー(Commander)、Ctrl+N の種類(QuickAdd)を足してもかまいません。新しい版が来ても残ります。ただし上の表のキーとぶつかったら、上の表のほうが勝ちます。そのときは準備の bat の画面と最後の「手でやること」に「キーがぶつかりました」と出るので、自分のほうに別のキーを付け直してください。上の表のキーを自分で変えた場合も、版が来ると元に戻ります。

## 1日の流れ

### 朝

1. 個人 vault で今日のデイリーノートを開きます(Ctrl+P →「today」→ Periodic Notes の「Open today's daily note」)。
2. 先頭に「同期プログラムから」の囲みがあれば読みます。共有されなかったノートと直し方が出ています。
3. 「タイムライン」に今日の予定を書きます。`- [ ] 09:30 - 12:00 [[保圧を変えて試作する]]` の形です。延びそうなら、Day Planner のタイムラインでブロックの端をドラッグすると時刻が書き換わります。
4. 「今日までの備忘録」には、どのノートに書いたチェックボックスでも、期日が今日までのものが自動で集まります。

### 仕事中

- 思いついたことは、デイリーノートの「メモ」か、今やっている仕事のノートに書きます。`00_inbox/` にファイルを作らなくてかまいません。
- 物や値の名前(PA66、保圧、ヒケ など)は選んで Ctrl+K。ノードに別名があれば、そのノードの属性欄の aliases に足します(`aliases: [米, お米]`)。
- 5分でできる細かい仕事は Ctrl+L でチェックボックスに。期日をつけると(`📅 2026-10-31`)、その日のデイリーノートに出ます。
- 写真・PDF・Excel・pptx は、ノートに貼るかドラッグするだけです。ファイル名はそのままでかまいません。行き先がわからないファイルだけ `00_inbox/` に置きます。
- スマホの写真は、Box アプリで共有の `00_inbox/` に上げ、PC でノートにドラッグします。
- 大きいデータ(測定データ・CAD・動画など)も、まずはノートに貼ってかまいません。いったん vault の `_仕組み/attachments/<id>/` に入りますが、同期プログラムが vault の外の Box `開発データ/` へ移し、ノートのリンクを `file:///…` に書き換えます。vault に残るのは画像・PDF・20MB 未満の動画だけです。
  - 共有する前のノートの添付は `開発データ/_個人/<名前>/<id>/`、共有されたら `開発データ/<プロジェクト>/<id>/` へ移ります。`開発データ` はチーム全員が見られるフォルダです。
  - 貼らずに、最初から `開発データ/` などに置いて、ノートからリンクだけ張ってもかまいません。
  - 機密フォルダの添付は動かしません。
- 図は Ctrl+D。枠1つが「1枚」です。Excel のグラフや画像は Ctrl+V で貼れます。2枚目からは、Excalidraw で枠を選んで「フレームへのリンクをコピー」で貼り、`#^frame=` を `#^clippedframe=` に書き換えます。

### 帰る前

- 今日のメモで、イシューやタスクになりそうな行があれば Ctrl+I / Ctrl+T を押します。迷うものは残しておいてかまいません。1週間たったものは金曜に片付けます。

## イシューを作る(心配なこと)

イシューは案につけます。成果物候補のノートの「部分の案」に案を1行ずつ書いて Ctrl+U を押すと、部分の案のノートになります。案が実現する仮説は、「価値の仮説を実現できるか」に `[[仮説]]` と書き、右クリック →「関係としてつなぐ」で 価値仮説 に入れます。候補ごとに「本当にこの案で仮説を実現できるか」を考え、それを脅かす心配をイシューにします。

**急ぐとき**: 心配を1行書いて Ctrl+I。impact は「未判定」で入り、金曜に PL が決めます。属性 脅かす には、いちばん近い設計案(なければ仮説)が自動で入ります。

**ゆっくり作るとき**: Ctrl+N →「イシュー」→ 名前を打ち、属性欄で次を選びます。

| 属性 | 答え方 |
| --- | --- |
| 名前 | 「〜のおそれ」で終わる文。例: スリープ電流が大きく電池が3年もたないおそれ |
| impact | 上から順に はい / いいえ。答えで開発の方向が変わる → **方針**。候補がいくつか消える → **絞込**。解けないと出荷できない → **出荷**。遅れやコスト増になる → **中**。改善になる程度 → **小** |
| speed | 1週間以内に今の人・設備・予算で試せる → **すぐ**。試作発注・回答待ちなどが要る → **時間がかかる** |
| project | プロジェクト名(台帳と同じ書き方)。すべてに関係するなら `共通` |
| 脅かす | 脅かす設計案(なければ価値の仮説)。K-Plex では設計案の右に出る |

- **迷ったら「出荷」「すぐ」**。priority(1〜4)は impact と speed から自動で決まるので、書きません。
- DR や打ち合わせで出た指摘は、impact 中以上だけイシューにします。小は議事録に残すだけです。
- 同期プログラムが動いていれば、イシューとタスクの最後の「類似・参考ナレッジ」に、同じノードを使う他のプロジェクトのイシューや使えるナレッジが足されます。着手する前に目を通してください。

## タスクを進める

- **タスクのノートにするのは、半日以上かかってリスクを下げる仕事だけ**です。それ以外はチェックボックスで十分です。
- イシューのノートで、やることを1行書いて Ctrl+T。parent にそのイシューが入ります。
- 同時に進めるのは1人3件まで。回答待ち・納品待ちは status を「待ち」にすれば数えません。priority 1 が動いている間は、priority 3・4 に手を出しません。
- status は 未着手 → 進行中 → (待ち)→ 確認待ち → 完了 です。やめると決めたら「中止」にします。消しません。
- 期限を変えたら due を書き換えるだけです。最初の期限は同期プログラムが別に残します。

## タスクを終える

終わったら、イシューのリスクがどう変わったかを残します。重さはイシューの impact で変わります。

| イシューの impact | 残すもの | 確認 |
| --- | --- | --- |
| 方針・絞込・出荷(impact 大) | ナレッジ図(Excalidraw、画面1枚)とナレッジのノート。わかったことを関係するノードにも書く | もう1人に見てもらう |
| 中 | タスクの「リスクはどう変わったか」に、写真と数値を3行 | 自分で読み返す |
| 小 | タスクの「リスクはどう変わったか」に1行 | 自分で読み返す |

**impact 大のとき**

1. タスクのノートを右クリック →「ナレッジにする」。`05_ナレッジ/` にナレッジができ、risk_reduction に `"[[イシュー]] 出荷→?"` が入ります。`?` を変わったあとの impact に直します(効かなかったら `出荷→出荷`。これも残します)。
2. usefulness を選びます。A: 他のプロジェクトでもそのまま使える。B: 同じ種類の製品・工程なら使える。C: この案件限り。
3. ナレッジのノートで Ctrl+D を押すと、図が2枚入ります。1枚目のナレッジ図は、左に実施前のリスク、真ん中にやったこと、右に実施後のリスクとわかったことを、スクロールせずに見える1枚に描きます。2枚目のトレードオフ曲線は、軸の名前と単位を書き換え、試した結果を点で置きます(案ごとに線を1本、目標の線を1本)。曲線にならない仕事なら、ノートの「トレードオフ曲線」の見出しごと消します。
4. わかったこと(例: 保圧を上げるとヒケが減る)を、関係するノードの「わかっていること」に書き戻します。
5. タスクの status を「確認待ち」にし、review_request に頼む人を書きます(`review_request: [佐藤]`)。確認を待たずに次のイシューへ進んでかまいません。

**最後に**: タスクを「完了」にし、イシューの status(未対応 / 対策中 / 低減済み / 解消 / 中止)を直します。

**確認を頼まれたら**: `00_タスク一覧.base` の「確認待ち(確認する人ごと)」に自分宛てが出ます。ナレッジ図・数値・ノードへの書き戻しを見て、よければナレッジの reviewed_by に自分の名前を足します。直してほしいことは本文に書かず、本人に伝えます。

## 対策から新しい心配が生まれたら

タスクや実験・試作記録の「リスクはどう変わったか」「判定」に新しい心配を1行書いて Ctrl+I を押します。元のイシューと同じ設計案が 脅かす に、今のタスクが previous に入り、世代(generation)も1つ増えます。新しくわかった構造は、元の設計案の「わかったこと」にも書き足します。

## 会議と実験の記録

| 記録 | 作り方 | 書くこと |
| --- | --- | --- |
| 議事録 | Ctrl+N →「議事録」 | 出た指摘は impact 中以上をイシューに(行で Ctrl+I)。決まったことは Ctrl+L か Ctrl+T |
| 実験・試作記録 | Ctrl+N →「実験・試作記録」 | 条件・測定結果・判定を毎回同じ形で。数値は単位つき。重いデータは添付すれば同期プログラムが `開発データ/` へ移す |

## 共有と機密の決まり

- 書かなければチームに共有されます。共有したくないノートだけ、属性欄に `visibility: 個人` と書きます。
- `90_共有/` のノートは他の人のものです。編集しません。書き足したいときは自分のフォルダ(`02_ノード/` など)へ移して編集すると、次の同期で共有へ戻ります。
- いらなくなったノートは消さず、`99_archive/` へ移します。
- 顧客から受け取った図面・仕様書・測定の生データは、機密フォルダに置きます。ノートには顧客名・図番・設備名を書きません。顧客名を伏せた数値(例: ある顧客の設備は月2回止まる、要求荷重 500N)は書いてかまいません。
- 機密を指すときは、属性欄に `secret_refs: ["[[案件A]]"]` と、共有の「機密の窓口」ノートへのリンクを書きます。機密フォルダの名前や事実ノートの名前は書きません。

## 書き方の決まり

| 使う | 使わない |
| --- | --- |
| `[[ ]]` のリンク(キーで作る) | 見出しへのリンク `[[水#性質]]`、ブロック参照 `^id` |
| 図の引用 `![[…/fig_<ノートのファイル名>.excalidraw#^clippedframe=frame1]]`(Ctrl+D が入れる) | それ以外の `![[ ]]` 埋め込み、Canvas |
| 普通の引用 `>` | コールアウト `> [!note]` |
| 属性欄の値 | 本文の #タグ だけに頼ること |

- ノートの名前に `# | [ ] ^ : \ /` を使いません。
- K-Plex は見るだけに使います。K-Plex の中でノートを作ったり(Ctrl+矢印)、中心のノートの編集欄で書いたりしません。別のノートを上書きしたことがあります。

## 困ったとき

| こんなとき | こうする |
| --- | --- |
| キーを押しても何も起きない | Templater の「Trigger Templater on new file creation」がオンか確かめる |
| 右上に「人の記号が見つかりません」 | 個人 vault の `_仕組み/個人設定.md` に name と number を書く |
| 作ったノートの parent が空 | 右上に理由が出ている。元のノートの parent(たどった先の候補や仮説)を直す |
| タブや一覧に id つきの名前が出る | テンプレートを使わずに作った古いノート。属性欄の aliases に名前を書く |
| 押し間違えて作った | 作ったノートを右クリック →「削除」(ゴミ箱 `.trash` に入る)。元の行は Ctrl+Z で戻す |
| 共有されないノートがある | 今日のデイリーノートの先頭と `_仕組み/同期レポート.md` に理由が出る |
| Obsidian で vault が開けない(保管庫を選ぶ画面が出る) | 管理者が vault の名前を変えたとき。「保管庫フォルダを開く」で新しい名前のフォルダを開き、Templater の「Trigger Templater on new file creation」がオンか確かめる |
| 同期プログラムに「止めました: 個人 vault が見つかりません」 | 管理者に知らせる(新しい場所が自動で見つからなかった) |
| 同じノートの「競合」ファイルができた | 自分では消さず、金曜の定例で PL とまとめる |
| Ctrl+J を押しても何も起きない | まだ入っていない。今の仕事が priority の高いイシューにつながっているかを、自分で見る |

わからないことは PL に聞いてください。
