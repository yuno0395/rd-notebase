# システム管理者 普段の仕事

> 正本は rd-notebase の `docs/マニュアル/`。仕様書 v0.53・要件書 v0.27 に合わせています。

システム管理者の普段の仕事は少なく、週に数分の見回りと、ときどき版を出すことです。同期プログラムは止まっても知見が消えない作りなので、慌てなくてかまいません。

## いつ何をするか

| いつ | やること |
| --- | --- |
| 毎週(金曜の定例の前に数分) | 同期の見回り(下の 1) |
| 月曜の朝 | 週報ができているか確かめる |
| 直したいことが出たとき | 版を出して配る(下の 2) |
| 人が増えた・抜けたとき | メンバーの出入り(下の 3) |
| 顧客の資料を扱う案件が始まったとき | 機密フォルダを作る(初期設定の 5) |
| 同期プログラムが止まったとき | 止まったときの手順(下の 4) |
| 年1回 | 停止訓練(下の 5) |
| vault の名前を変えたいとき | vault の名前を変える(下の 6) |

## 1. 同期の見回り

1. 自分の個人 vault の `_仕組み/同期レポート.md` の「警告」を読みます。ノートの中身の話(未入力・競合・同じ名前)は PL が金曜に片付けるので、システム管理者が見るのは仕組みの警告です。

| 警告 | すること |
| --- | --- |
| 同じ id(別のノートに同じ id) | 2人が同じ番号を使っていないか、メンバー.csv を見る |
| 人の記号が食い違っています | その人の個人設定.md とメンバー.csv をそろえる |
| チーム設定が読めない | `_仕組み/同期設定.yaml` を直す(全員の同期が止まっている) |
| パスが長すぎる(260 文字) | 本人にノート名を短くしてもらう |
| 機密へのリンク・機密フォルダの名前が入っている | 本人に secret_refs を窓口ノートへのリンクに直してもらう。機密フォルダの中に知見(ナレッジ・イシュー・タスク)があれば、個人か共有へ移してもらう |
| 週報を作るところで止まりました | 下の「週報ができていない」 |
| 設定の場所がおかしいので、同期を止めました | その人の config.yaml の personal・shared・secret を直す(vault でない場所、共有クラウドフォルダの一番上、重なった場所を書いている)。直すまで何も書き換えないので、急がなくてよい |
| Publish・Sync・Obsidian Git がオン、外のサービスの鍵、配っていないプラグイン | 本人にオフにしてもらう。試したいプラグインなら個人 vault だけで、金曜の定例へ(「7. 守ること」) |

2. 各 PC で同期が動いているか、メンバーに聞きます。同期レポートの「記録」の時刻が新しければ動いています。
3. 共有クラウドフォルダの容量を見ます。重い添付は `開発データ/` に移る決まりです。共有 vault の `_仕組み/attachments/` に重いファイルがたまっていたら、`notesync recover` で移します。

**週報ができていない**

- 月曜に、config.yaml に `report` を書いた PC のどれかで同期プログラムが動いていたかを確かめます(週報は誰の PC でも作ります)。
- 作り直すときは、その PC で `notesync weekly` を実行します。今回だけ節を外すなら `notesync weekly --hide 同じノード,機密`、載せる節を絞るなら `--only 出荷準備度,担当者` です。
- 毎回外したい節は、`_仕組み/同期設定.yaml` の `report_sections` で `false` にします。

## 2. 版を出して配る

仕組み(テンプレート・設定・スクリプト・仕様書・マニュアル)は、配った物を直さず、GitHub の正本を直して版を出します。

**直す**

1. 直したいことは、金曜の定例か GitHub の issue で集めます。現場の困りごとは、週報テンプレートの「仕組みの困りごと」にも出ます。
2. 正本(`C:\dev\rd-notebase`)を直します。テンプレートの正本は `vault/共有/_仕組み/templates/` の1か所だけです(個人・機密用には組み立てるときに写ります)。
3. `docs/00_仕様書.md` の変更履歴に、版と直したことを書きます。マニュアルに関係する直しなら、`docs/マニュアル/` も直します。
4. 同期プログラムを直したら、`sync\` で `pytest` を実行し、テストが通ることを確かめます。
5. Ctrl+I などのスクリプト(`_仕組み/templates/_scripts/`)を変えるときは、書く前に Yu の確認をもらいます。

**bat で出して配る**

1. 直したものを GitHub の正本に入れてから、`C:\dev\rd-notebase\tools\システム管理者.bat` を押し、「新しい版を出して配る」(Enter)を選びます。
2. 出す版の番号を聞かれます。Enter で次の番号(0.3.0 なら 0.3.1)です。
3. bat が正本を最新にし(git pull)、自動テストを走らせ、組み立て、プラグインの本体をそろえ、仕様書の変更履歴から `この版で変わること.md` を作ります。テストが落ちたら、そこで止まって何も配りません。
4. 「これからすること」(共有の `_仕組み/tools/配布/<版>/` に置く、共有 vault を今の版にする、自分の環境を上げる)を読んで Enter を押します。最後に GitHub にタグを打つか聞かれます。
5. メンバーには「新しい版を出しました。準備の bat を押してください」と伝えます。伝えなくても、各自の同期レポートの「対応が必要」に出ます。
6. 古い版のままの PC は、次に bat を押したときの最初の画面の「各 PC の版」でわかります。

プラグインの「要対応」が出たら、下の「組み立てて置く」のとおり LICENSE やソース zip を手で置き、同じ版の番号でもう一度 bat を押します。下は bat が中でしていることと、bat が使えないときの手順です。

**組み立てて置く**

```
cd C:\dev\rd-notebase
python tools\build.py 0.3.0
```

続けてプラグインの本体をそろえます。Obsidian で配るプラグインを入れ、動きを確かめた設定フォルダを指します(ネットを使います)。

```
python tools\plugins.py pack 0.3.0 --from <個人 vault>\.obsidian
```

`dist\0.3.0\プラグイン\` に、プラグインごとの本体(main.js・manifest.json・styles.css)と LICENSE、AGPL・GPL のもののソース zip(`ソース\`)、出典一覧 `プラグインの出典.md` ができます。「要対応」が出たら、書かれたとおり LICENSE やソース zip を GitHub のリリースから手で置き、出典一覧のライセンスの欄を直します。プラグインの本体は rd-notebase には入れません(`dist\` は Git に入りません)。社外や有償では配りません。

`dist\0.3.0\` を共有 vault の `_仕組み/tools/配布/0.3.0/` に置き、GitHub に同じ名前のタグをつけます。

**当てる**(ふつうは各自が準備の bat を押せば当たる。下は手で当てるとき)

ファイルは2種類です。`manifest.toml` に一覧があります。ノートには触れません。

| 種類 | 例 | 当て方 |
| --- | --- | --- |
| 仕組みのファイル(system) | 共有: `00_README.md`、`00_仕様書.md` などの写し、`00_マニュアル/`、`00_*.base`、`_仕組み/templates/`、`_仕組み/設定/`。個人: `00_README.md`、`00_*.base`、`_仕組み/templates/`、`.obsidian/hotkeys.json`、`.obsidian/plugins/` | 上書きする |
| 最初だけのファイル(seed) | `同期設定.yaml`、メンバー.csv、`個人設定.md`、`同期レポート.md`、個人 vault の `.obsidian/` のそれ以外(`app.json`、`community-plugins.json`) | ないときだけ置く。あれば触らない |

1. 共有 vault の仕組みのファイルを、システム管理者が上書きします。
2. 個人 vault の仕組みのファイルは、各自が `_仕組み/tools/配布/<版>/個人/` から自分の個人 vault へ上書きコピーします。手順をメンバーに伝えます。
3. 配ったプラグインの設定(`plugins/`)は、2 で一緒に上書きされます。キー(`hotkeys.json`)・右クリックメニュー(Commander)・QuickAdd は上書きせず合わせます(配るものは入れ直し、各自で足したものは残す)。キーが配る側とぶつかったときは配る側が優先で、本人の bat の画面に「キーがぶつかりました」と出ます。新しい版で配るキーを足すときは、みんなが使っていそうなキーを避けます。`community-plugins.json` は上書きしません(各自が足したプラグインが外れるため)。プラグインの本体と、共有・機密 vault の `.obsidian-<番号>_<PCの記号>/` の設定は、各自に `プラグインを入れる.bat` を1回動かしてもらえば入ります(版が同じプラグインは触らず、各自が足したプラグインは外しません)。新しいプラグインを個人 vault に配る版では、その名前を各自の `community-plugins.json` に足してから bat を動かしてもらいます。
4. フォルダの構成や属性の名前が変わる版では、移し替えのスクリプトを使います(版ごとに1本。飛ばした版があれば古い順に全部)。ふつうは準備の bat が当てます。手で試すときは `python tools\migrate_v055.py <vault> ...`(`--run` なしで試し、控えの zip ができることを確かめてから `--run`)。
5. Obsidian を開き直し、`_仕組み/設定/導入手順.md` の「確かめること」のうち、変えたところを試します。

## 3. メンバーの出入り

**入るとき**

1. `システム管理者.bat` →「メンバーを足す」で、名前と6桁の番号を打ちます。メンバー.csv に1行足し、自分が権限を持つ機密フォルダの写しにも足します(手で足すときは初期設定の 4)。
2. 共有 vault・開発データ・報告フォルダに招待します。担当する機密フォルダがあれば、それにも招待します。
3. 自分に権限のない機密フォルダの `_仕組み/tools/メンバー.csv` は、その PL に bat を押してもらえば共有のものに入れかわります(新しく作るときだけ。今ある機密フォルダには手で同じ行を足します)。
4. [[01_チームメンバー_初期設定]] を渡し、共有 vault の `_仕組み/tools/準備/チームメンバー.bat` を押してもらいます。
5. PL に、台帳の members に足してもらいます。

**抜けるとき**

1. 共有クラウドフォルダの共同作業者(見られる人)から外します(機密フォルダを忘れずに)。
2. メンバー.csv の行は消しません。番号は欠番にし、ほかの人に使い回しません。ノートの id にその人の記号が残っているためです。
3. その人の個人 vault で visibility: 個人 以外のノートは、すでに共有に集まっています。PL と、引き継ぐノートの担当(owner)を決めます。
4. PL に、台帳の members から外してもらいます。

## 4. 同期プログラムが止まったとき

知見はプログラムがなくても読み書きできます。止まっている間はこうなります。

| 止まった仕事 | どうなるか | 人がやること |
| --- | --- | --- |
| id 付け | テンプレートを使わずに作ったノートに id がつかない | そのまま書いてよい。再開後につく |
| 集約・再配布 | 共有 vault と `90_共有/` が新しくならない | 他の人の知見は共有 vault を直接開いて読む。急ぐものだけ手で共有へコピーする(下) |
| 重い添付の移動 | `_仕組み/attachments/` にたまる | 何もしなくてよい。再開後に移る |
| 週報 | 作られない | PL が台帳(節目の表と判断してほしいこと)を上司に渡す |
| priority などの自動入力 | 空のまま | 一覧(Bases)は自分で計算するので、priority 順は見られる |

**手で共有へ出すとき**: 共有 vault に同じ id のファイルがないか検索し、なければ同じ種類のフォルダへコピーします。添付の `_仕組み/attachments/<id>/` も一緒にコピーします。あれば上書きせず、PL と中身をまとめます。id のないノートと、機密フォルダのものは手でも出しません。

**再開するとき**

1. その PC で `notesync once --dry-run` を実行し、同期レポートを確かめます。
2. 止まっている間に共有 vault へ直接書かれたノートがあれば、`notesync recover` → 確かめて `notesync recover --run`。
3. `notesync once`(`2_1回同期.bat`)で1回動かしてから、`3_同期を続ける.bat` かタスク スケジューラに戻します。

**前回の記録が消えたとき**: 個人 vault の `_仕組み/記録/同期の記録.json` が消えても、同期プログラムは個人 vault と共有 vault を見比べて作り直します。違うものは上書きせず、競合として残します。上書きの前の内容は、同じ場所の `backup\` に30日分残っています。

## 5. 年1回の停止訓練

月末の振り返りの回で日程を決め、全員の同期プログラムを止めたまま1週間運用します。上の「止まったとき」の手順で回らないところがあれば、仕様書を直して版を出します。

## 6. vault の名前を変える

個人・共有・機密の vault は、フォルダの名前を変えてかまいません(親のフォルダの名前を変えたり、別のフォルダへ動かしたりしてもかまいません)。各 PC の同期プログラムが次の同期で新しい場所を見つけ、その PC の `config.yaml` を自分で書き直します。メンバーの PC を1台ずつ回る必要はありません。

**変える前に**

1. 変える vault を、その前に1回は同期しておきます。同期プログラムが vault に印(`_仕組み/記録/vault_id.txt`)を置き、どこにあったかを覚えます。最初の同期で自動でできるので、ふつうは何もしなくて済みます。
2. 名前を変える vault を使っている人に、Obsidian を閉じてもらいます(共有 vault ならメンバー全員、機密フォルダならその担当)。

**変える**

3. エクスプローラーか共有クラウドの画面(Box・OneDrive など)でフォルダの名前を変えます。動かす先は、元の親フォルダの下か、その隣のフォルダの下(例: `<クラウド>\個人\` から `<クラウド>\チーム\`)にしてください。それより遠くへ動かすと見つけられないので、その PC の `config.yaml` を手で直します。
4. 自分の PC で `notesync once` を1回動かします。画面かデイリーノートの同期レポートに「設定を直した: 古い場所 → 新しい場所」と出れば終わりです。直す前の設定は `config.yaml.<日時>.bak` として同じ場所に残ります。

**各メンバーにやってもらうこと**(名前を変えたことを伝えるときに一緒に送ります)

5. Obsidian を開くと元の保管庫が開けないので、保管庫を選ぶ画面の「保管庫フォルダを開く」から新しい名前のフォルダを開きます。一覧に残った古い名前は外しておきます。
6. 設定 → Templater で「Trigger Templater on new file creation」がオンか確かめ、オフならオンにします(開き直すとオフに戻ることがあります)。共有・機密の vault なら、設定フォルダの上書き(`.obsidian-<6桁の番号>_<PCの記号>`)も確かめます。
7. 同期プログラムは何もしなくてかまいません。次の同期で、その PC の設定も自動で直ります。

**うまくいかないとき**

| 出たメッセージ | こうする |
| --- | --- |
| 「止めました: 個人 vault が見つかりません」 | 新しい場所が遠すぎるか、印のない vault。その PC の `%APPDATA%\知見同期\config.yaml` の `personal:` を新しい場所に書き直す。古い名前のフォルダは作られていないので、片付けはいらない |
| 「機密フォルダが見つかりません。…同期を止めました」 | `secret:` の行を新しい場所に書き直す。名前を変えていないなら、共有クラウドフォルダの権限が外れていないか確かめる。機密の言葉の確かめができないので、直るまで共有へは送らない |
| 「似たフォルダが 2 つあるので選べません」 | vault を丸ごとコピーしたときに出る。その PC の `config.yaml` を、使う方の場所に手で直す |

- 開発データと報告フォルダの名前は変えないでください。ノートの中の重い添付のリンクが、開発データの場所を指しているためです。
- 試しの PC(`Desktop\Box_試し\_同期の試し\`)では、`config_Yu.yaml` などは自動で直りますが、`フォルダ整理.bat` に書いた場所は手で直します。

## 7. 守ること

- ファイルを消しません。古くなったものは `99_archive/` へ移します。
- 機密フォルダの中身を、どこへもコピーしません。権限は共有クラウドフォルダの共同作業者(見られる人)で決めます。
- 正本(リポジトリ)を共有クラウドフォルダの中に置きません。控えは Git のバンドル(1ファイル)にして置きます。
- 正本は public です。入れてよいのは仕組みと作り物の見本だけで、実際のノート・顧客の資料・社内の名前やパスは入れません。版を出す bat は、GitHub にまだない手元のコミットがあるとタグを送らずに知らせます。そのときは `git log @{u}..HEAD` で中身を確かめてから送ります。
- 月に1回、共有クラウドの画面で共有 vault・開発データ・報告・機密のフォルダの共同作業者と共有リンクを見ます。社外の人がいない、共有リンクがないか社内の人だけ、を確かめます。
- Obsidian の Publish・Sync、Obsidian Git、AI などの外のサービスの鍵は使いません。Claude などに PC を操作させるときは、試しの vault だけを開かせます。
- 共有 vault の `00_仕様書.md` やテンプレートを、その場で直しません。直すのは正本で、次の版で写しが入れ替わります。
