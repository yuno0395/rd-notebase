# 使い方マニュアルの案内

> この Markdown の正本は GitHub のリポジトリ rd-notebase の `docs/マニュアル/` にあります。共有 vault の `00_マニュアル/` には、版を出すたびに写しを置きます。ここでは直さないでください。
> 作成: Yu ・ 書き出し: 2026-10-25 ・ 仕様書 v0.42 に合わせています

開発ノートの使い方を、立場ごとに「初期設定」と「普段の仕事」の2つに分けて書いています。自分の立場の2つだけ読めば使えます。

| 立場 | どんな人 | 初期設定(最初に1回) | 普段の仕事 |
| --- | --- | --- | --- |
| チームメンバー | ノートを書く全員 | [[01_チームメンバー_初期設定]] | [[02_チームメンバー_普段の仕事]] |
| プロジェクトリーダー(PL、まとめ役) | プロジェクトの目的・優先順位・見込みに責任を持つ人 | [[03_プロジェクトリーダー_初期設定]] | [[04_プロジェクトリーダー_普段の仕事]] |
| システム管理者 | 仕組みの面倒を見る人(共有クラウドフォルダのフォルダと権限、配布、同期プログラム) | [[05_システム管理者_初期設定]] | [[06_システム管理者_普段の仕事]] |

K-Plex(つながりの図)の見方は、立場に関係なく [[07_K-Plexの使い方]] にまとめています(絵つき)。

- PL もノートを書くので、チームメンバーの2つを先に読んでください。PL のマニュアルには、その上に足すことだけを書いています。
- 「システム管理者」は、週報を読む管理者(上司)とは別の役割です。上司は Obsidian を使わず、共有クラウドフォルダの `開発ノート_報告/週報の一覧.html` をブラウザで開いて週1回読むだけです。
- 当面は2人なので、1人が2つ以上の立場を兼ねてかまいません。
- **共有クラウドフォルダ**は、PC 上で同期されるフォルダのことです。会社で使っているものなら、Box Drive・OneDrive・Google ドライブ・社内 NAS(ネットワークドライブ)のどれでもかまいません。マニュアルの例の `<クラウド>\` は、その一番上のフォルダ(例: `C:\Users\<ユーザー名>\Box\`、`C:\Users\<ユーザー名>\OneDrive - 会社名\`、`\\nas\開発\`)です。
