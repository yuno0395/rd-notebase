## 目的と範囲

各メンバーの個人 vault と Box 上の共有 vault の間で、知見ノートをプロジェクトごとに集め、配り直す常駐プログラム。Obsidian の外で動き、手でのコピペ・id 付け・重い添付の移動を自動化する。運用ルールの正本は同じフォルダの 00_仕様書.md(まとめ役向け)で、この要件書はプログラムが守ることだけを書く。現場向けの手順は 00_現場向け1枚.md にある。

プログラムが担う仕事は次の4つ。

1. **id 付け**: id のないノートに id を振り、ファイル名とリンクを直す。
2. **集約**: 個人 vault のノートを、条件を満たしたものだけ共有 vault へ振り分けてコピーする。
3. **再配布**: 共有 vault のノートを、参加しているプロジェクト分だけ個人 vault の 90_共有/ へ配る。
4. **重い添付の移動**: vault 内に入れない添付を 開発データ/ へ移し、リンクを書き換える。

あわせて、機密フォルダの中身を外へ出さないことを守る(F-40)。pptx の取り込み・書き出しなどはおまけとして足す。

## 前提環境

| 項目 | 前提 |
| --- | --- |
| OS | Windows 10 / 11 |
| クラウド | Box。各自の PC に Box Drive を入れ、`C:\Users\<ユーザー名>\Box\` 以下に見えている |
| フォルダ | 個人・共有・機密の3種類を、Box の中の好きな場所に別々に置く。場所は各自の個人設定に書く(仕様書「フォルダ構成」) |
| 共有 vault | 共同作業者: チーム全員 |
| 個人 vault | 共同作業者なし。本人のみ |
| 機密フォルダ | いくつでも。名前は自由。共同作業者: その案件の担当者だけ。事実と原本だけを置く |
| 開発データ | 共有 vault の重い添付の置き場所(vault の外) |
| 実行場所 | 各メンバーの PC で1つずつ動かす。自分の個人 vault と共有 vault を扱い、他人の個人 vault には触らない。機密フォルダは id 付けだけを行い、中身をどこへもコピーしない |
| Obsidian | なくても動く。起動中でも安全に動く |

**Box Drive について気をつける点**

- Box Drive はファイルを必要なときにダウンロードする。読むだけでダウンロードが走るため、変更の検知は更新日時とサイズで行い、中身は必要なファイルだけ読む。
- 個人 vault・共有 vault・権限のある機密フォルダは Box Drive の「オフラインで利用可能」をオンにする(Obsidian を速くするためと、同期の読み込みを安定させるため)。開発データ/ はオフのままでよい。
- Box 側で同時編集があると、Box が名前を変えた複製を作ることがある。プログラムはこれを見つけてレポートに出す(複製の名前の付け方は導入時に実機で確認する)。
- 個人 vault の .obsidian(設定フォルダ)は同期の対象外にする。

## 機能要件

「必須」は最初の版で作るもの、「後でよい」は運用しながら足すもの。

機能は「核」と「おまけ」に分け、おまけは別の部品にする。おまけが壊れても核は止めない。

- 核: F-01〜21、F-23、F-28、F-34、F-35、F-40、F-44(id 付け・集約・再配布・競合・添付・レポート・記録の作り直し・機密の守り・人の記号)
- おまけ: F-22、F-24〜27、F-29〜33、F-36〜39、F-41〜43、F-45、F-46(通知、取り消し、タスクトレイ、previous・generation、週報、自動入力、類似・参考ナレッジ、世代ツリー、やめる候補、因果の距離、pptx の取り込みと書き出し、inbox の残り、今の仕事、仕組みの更新)
- 最初は核だけを作る。核ができるまでは、仕様書「同期プログラムができるまでの仮運用」で運用する。
- どの機能も、止まっている間は人が手で代わりをできること(仕様書「同期プログラムが止まっても回るようにする」)。プログラムだけが読める形式でノートに書かない。

## 処理の流れ

ファイルの変更を検知したときと、一定間隔(初期値 3 分)ごとに、1回分の同期を次の順で行う。各手順は前の手順が終わってから始める。

1. **待つ**: 対象のノートが 10 秒以上変更されていないことを確かめる(入力中のノートに触らないため)。
2. **id 付け**(F-01〜04): 個人 vault の id のないノートに id を振る。
3. **重い添付の移動**(F-17、17b、18): _仕組み/attachments/<id>/ の対象ファイルを 開発データ/ へ移し、リンクを書き換える。
4. **差分を数える**(F-14): 前回の記録と比べて、個人側だけ・共有側だけ・両方のどれが変わったかを分ける。
5. **集約**(F-05〜09、19、20): 個人側だけ変わったノートを、条件を確かめて共有 vault へコピーする。同じ id の別ノートがあれば集めずに警告する(F-08)。
6. **再配布**(F-10〜13): 共有側だけ変わったノートを 90_共有/ へコピーする。
7. **競合**(F-15、16): 両方変わったノートと Box の複製を、上書きせずに残す。
8. **記録と報告**(F-21): 今回の内容を記録し、同期レポートを更新する。

手順 5 と 6 で書き込む前に、対象ファイルが手順 4 のあとに変わっていないかもう一度確かめ、変わっていたら次の回に回す。

## 設定ファイル

設定は2つに分ける。各自の PC だけの設定と、チーム共通の設定。

**個人設定**(`%APPDATA%\知見同期\config.yaml`、Box には置かない)

```yaml
member: Yu                                   # 番号は個人設定.md とメンバー.csv から読む(F-44)
personal: C:/Users/yunos/Box/個人/開発ノート_Yu
shared: C:/Users/yunos/Box/チーム/開発ノート_共有
shared_data: C:/Users/yunos/Box/チーム/開発データ
report: C:/Users/yunos/Box/チーム/開発ノート_報告
secret:                                      # この PC で権限のある機密フォルダだけ(名前は自由)
  - C:/Users/yunos/Box/機密/顧客A
interval_minutes: 3
idle_seconds: 10
dry_run: false
```

**チーム設定**(共有 vault の `_仕組み/同期設定.yaml`、全員が同じものを使う)

```yaml
id_epoch: 2026-01-01T00:00:00+09:00   # id の時刻の起点
keep_in_vault:
  images: [png, jpg, jpeg, gif, webp, svg]
  pdf: true
  video: [mp4, webm, mov]
  video_max_mb: 20
report_runner: yu            # 管理者向け週報を作る1台(F-29)
report_sections:             # 週報に載せる節(F-29)。false で外す。見込みはいつも載せる
  出荷準備度: true
  候補の数: true
  マイルストーン: true
  目的に沿わない: true
  反論のついた仮説: true
  同じノード: 自動           # 進めているプロジェクトが2つ以上あるときだけ載せる
  行き詰まり: true
  担当者: true
  機密: true
```

- プロジェクトとメンバーの対応は設定に書かず、共有 vault のプロジェクトのノート(members 属性)を正として読む。人の番号は `_仕組み/tools/同期プログラム/メンバー.csv` を正とする。人が増えても1か所直せば済む。
- チーム設定が壊れていたら(YAML として読めないなど)同期を止め、レポートに出す。

## 同期レポート

個人 vault の `_仕組み/同期レポート.md` に、人が対応すべきものを上に、記録を下に書く。Obsidian でそのまま開け、リンクから対象のノートへ飛べる。

```markdown
# 同期レポート(最終更新 2026-10-24 10:32)

## 対応が必要
- [ ] 競合: [[0RBDMG4XGV_肉厚部のヒケで外観不良になるおそれ|肉厚部のヒケ…]] を佐藤さんも変更しています。競合ファイルを見て統合してください
- [ ] 未入力: [[0RAYFN4XGV_水|水]] の usefulness が空です(共有していません)
- [ ] 確認待ち: [[0RY1TD4XGV_保圧を変えて試作する_ナレッジ|保圧…]] は impact 大のため確認者が必要です
- [ ] 同じ名前: 「水」があなたと佐藤さんの2つあります

## 警告
- 同じ id: 0RAYFN4XGV(2026-10-23 10:12:05 作成)が佐藤さんの「鉄」にもあります。人の記号の設定を確かめてください(集めていません)

## 記録(新しい順、直近 30 日)
- 10:32 集約 2件 / 再配布 5件 / 添付移動 1件(成形条件.xlsx → 開発データ/樹脂カバー量産/…)
```

- 「対応が必要」は、原因がなくなったら次の同期で自動で消える。
- 詳しいログ(ファイルごとの操作とエラー)は `%APPDATA%\知見同期\logs\` に日ごとに残し、90 日で消す。

## 例外・エラーの扱い

迷ったら書き込まず、レポートに出して人に任せる。ファイルを消す処理は持たない。

| 起きたこと | プログラムの動き |
| --- | --- |
| Box Drive が止まっている、またはオフライン | 同期を見送り、次の回にもう一度確かめる |
| ファイルがまだダウンロード中・書き込み中 | そのファイルだけ次の回に回す |
| 属性欄(YAML)が壊れていて読めない | そのノートは触らず、行番号つきでレポートに出す |
| parent をたどっても project が決まらない | 集めず、「project 不明」とレポートに出す |
| リンク先のノードが共有にない | そのノードも集める条件を満たせば一緒に集める。満たさなければレポートに出す |
| 同じ id の別ノートが見つかった | 集めずにレポートに出す。人の記号の重複を疑う(F-44) |
| 移動先に同じ名前の添付がある | 同じノートの添付どうしでしか起きない。上書きせず、末尾に `_2` などをつけて移しレポートに出す |
| パスが Windows の上限(260 文字)を超えそう | 書き込まずレポートに出す(ノート名を短くしてもらう) |
| 予期しないエラー | その回の同期を中断し、ログに残して次の回に再開する。途中までの変更は記録から元に戻せる |

## 非機能要件

| 項目 | 要件 |
| --- | --- |
| 反映までの時間 | ノートを保存してから共有 vault に入るまで 5 分以内(Box の同期時間は除く)。添付の移動はドロップから 30 秒以内 |
| 軽さ | 待機中の CPU 使用率 1% 未満、メモリ 200MB 未満。ノート 1 万件でも 1 回の同期が 1 分以内 |
| 安全 | ファイルを削除しない。上書きする前に元の内容を `%APPDATA%\知見同期\backup\` に 30 日分残す |
| 文字コード | ノートは UTF-8、改行は元のファイルに合わせる。日本語のファイル名・フォルダ名を扱える |
| 属性欄の保存 | 書き換えるのは必要な項目だけ。他の項目の順番・コメント・書き方は変えない |
| 起動 | Windows のサインイン時に自動起動(タスクスケジューラ)。管理者権限なしで入れられる |
| 配布 | 1 つの exe(または zip を展開するだけ)で入れられる。Python などの別インストールを利用者に求めない |
| ツール非依存 | Obsidian やプラグインの内部データを読まない。Markdown と YAML だけを扱う |
| 人数 | 2 人で始め、100 人・プロジェクト 50 件まで、作り直さずに使える |
| ライセンス | 使うライブラリは商用利用できるものに限る |
| 保守性 | Python など普及した言語で書く。テスト用 vault(競合・同じ id・機密へのリンク・止まったあとの復旧などの例)と自動テストを同じリポジトリに置き、「テストが通れば直してよい」と言える状態にする。保守手順書(作り方・配り方・よくある障害)とソースの控え(Git バンドル)を共有 vault の _仕組み/tools/同期プログラム/ に置く |
| 止まっても困らない | プログラムが何か月止まっても、ノートと共有 vault は人が読み書きできる状態を保つ。プログラムだけが持つデータは、消えても F-34 で作り直せるものに限る |
