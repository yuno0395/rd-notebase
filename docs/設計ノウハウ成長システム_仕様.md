# 設計ノウハウ成長システム 仕様書

版：v0.4（草案・作り込み中）2026-10-22
これまでの検討は `docs/old/`（まず `docs/old/rd-notebase_試作のまとめ.pdf`）。この仕様書は白紙から書き直すもので、考え方の一部だけを引き継ぐ（11章）。

> この版は叩き台。【案】は提案で、確認が要る。未決事項は12章。

## 1. 目的

**ものづくり企業で、製品を設計するたびに会社の設計ノウハウが増え、次の設計が速く・確かになる仕組みをつくる。**

### 1.1 背景（いま困っていること）

- デザインレビュー（DR）や FMEA・FTA はよく行われている。しかし、それを支える**設計知が貯まっていない**ので、DR が形だけになりやすい。
  - 設計知の例：構造物の基本的な知見（剛性・振動・熱・摩耗などの効き方と限界）、開発段階の失敗とその原因。
- FMEA に残るのは、量産後の不具合だけ。開発の途中で分かった「やってはいけないこと」「効かなかった案」は、担当者の頭と個人のファイルに散らばる。
- 必要な技術や要求品質は、技術の動向で変わる。そのため、最初から目標性能を1点に決めにくい。
- 同じことを、人が替わるたびに調べ直し、試し直している。

### 1.2 目指す姿

- 開発の活動は、すべて「命題に対するリスクを減らすため」に行われる。何のためにやっているかが、いつでも分かる。
- 限られた工数を、価値への効き目が一番大きいリスクから順に使う。
- 活動で分かったこと（新しい知識・因果関係・どのリスクを減らしたか）は、A3 1枚にまとめて知見プールに入る。
- 次の開発では、知見プールのメカニズムと知識を使って、リスクを早く・安く見積もって減らせる。こうして設計ノウハウが育つ。

## 2. 基本の考え方：リスクを減らす活動だけをする

リーン設計開発では、**リスクを減らす活動しかしない**。開発は次の順で考える。

1. **命題を立てる**：開発で実現したいこと。例：顧客価値の最大化。
2. **リスクを挙げる**：命題が失敗するリスク（最大化できない原因になり得ること）を列挙する。
3. **メカニズムを推測する**：それぞれのリスクが、どういう因果のつながりで命題（顧客価値）に効くのかを推測する。
4. **リスクを減らすタスクを考える**：メカニズムを手がかりに、リスクを減らすには何をすればよいかを考える。
5. **優先順位を付ける**：タスクの優先度を、決まった式で数値にする（4章）。
6. **一番大きいものを実行する**：リスクを減らす。
7. **A3 にまとめて知見プールへ**：得られた新しい知識・因果関係・何のリスクを減らすためのタスクだったかを、A3 1枚にまとめて知見プールに入れる。
8. **繰り返す**：命題に対するリスクがなくなるまで、2〜7 を繰り返す。

- 「リスクを減らすためでないタスク」は、このシステムの上では作らない。
- 設計ノウハウは、このループを回した結果として知見プールに貯まる。貯めるための別の作業はしない。

## 3. 進め方（リスクを減らすループ）

```
 ┌──────────────────────────────────────────────────────────────┐
 │ 命題（例：顧客価値の最大化）                                    │
 └──────────────┬───────────────────────────────────────────────┘
                ↓
   ② リスクを列挙 ──→ ③ メカニズムを推測 ──→ ④ 減らすタスクを考える
        ↑               （因果のつながり）        （メカニズムを参考に）
        │                     ↑                          ↓
        │                     │ 参考にする          ⑤ 優先度を計算
        │                     │                          ↓
        │              ┌──────┴──────┐            ⑥ 一番大きいものを実行
        │              │  知見プール  │ ←── ⑦ A3 1枚にまとめて入れる
        │              └─────────────┘     （新しい知識・因果関係・
        │                                     減らしたリスク）
        └──── ⑧ リスクが残っていれば繰り返す。なくなれば命題は完了
```

**例：顧客が欲しい時に物が届く（命題の一部）**

| 段階 | 中身 |
| --- | --- |
| 命題 | 顧客価値の最大化（そのうち「欲しい時に届く」） |
| リスク | 予想最大の月産台数で発注されると、調達が間に合わず納期が遅れる |
| メカニズム（例） | 部品 X の調達リードタイムが受注から出荷までの要求より長い → 最大月産時に欠品 → 出荷が遅れる → 顧客の生産計画が崩れる → 顧客価値が下がる |
| タスク | 現行機種の部品表から、部品ごとの調達リードタイムと供給能力を集め、最大月産で試算する |
| 結果（A3 → 知見プール） | 部品 X が律速。12 週・月 ○台が上限（適用範囲：今の仕入れ先・今の部品構成）。リスクは「部品 X の供給能力」に絞られた → 次のタスク「別の仕入れ先で上限を上げられるか」 |

## 4. 優先順位の付け方

タスクの優先度は、次の式で計算する。**一番大きいものから実行する。**

```
優先度 ＝ 顧客価値量 × 感度 × 価値の寿命期待値 × 不確実性 ÷ 検証コスト
```

| 項 | 意味 | 大きいほど |
| --- | --- | --- |
| 顧客価値量 | そのリスクが関わる顧客価値の大きさ | 優先 |
| 感度 | リスクの因子が動いた時に、顧客価値がどれだけ動くか（メカニズムから見積もる） | 優先 |
| 価値の寿命期待値 | その価値が続くと見込まれる長さ（技術の動向ですぐ失われる価値は小さい） | 優先 |
| 不確実性 | 今どれだけ分かっていないか。知見プールに確かな知見があれば小さく見積もる | 優先 |
| 検証コスト | タスクにかかる工数・費用・期間 | 後回し |

### 4.1 入れ方：4項はお金で、不確実性は5段階の点数で【叩き台】

**見積もりの値そのものも不確かである、という前提で作る。** 4項は1つの値ではなく、幅（低い・最も確からしい・高い）で入れる。

| 項 | 入れるもの | 単位 | 入れ方の例（低い／最も確からしい／高い） |
| --- | --- | --- | --- |
| 顧客価値量 | 実数の幅 | 円／年 | この製品で顧客に届ける価値のうち、このリスクが関わる部分。例：1.5／2／3 億円／年 |
| 感度 | 実数の幅 | 割合（0〜1） | リスクが起きた時に、顧客価値量のうち失われる割合。例：0.2／0.3／0.5 |
| 価値の寿命期待値 | 実数の幅 | 年 | その価値が続く見込みの年数。例：3／5／7 年 |
| 検証コスト | 実数の幅 | 円 | 工数（人日 × 単価）＋ 試作・外注・設備などの費用。例：30／40／60 万円 |
| 不確実性 | 点数 | 1〜5 | 4.2 の5段階から選ぶ |

- よく分かっている値は、3つを同じにしてよい（幅なし）。
- よく分からない値ほど、幅を広く入れる。「分からない」ことを幅で正直に書く。
- 上の3項を掛けると、**リスクで失われる顧客価値の見込み（円）**になる。
- これを検証コスト（円）で割ると、「お金をかけた分の何倍の価値を守れるか」になる。それに不確実性の点数を掛けたものが優先度。

```
価値の損失見込み（円）＝ 顧客価値量（円／年）× 感度 × 価値の寿命期待値（年）
優先度 ＝ 価値の損失見込み（円）× 不確実性（1〜5）÷ 検証コスト（円）
```

- 金額で入れにくい時は、次の順で金額に置き換える【案】：
  1. 売上・利益・顧客の損失回避など、金額が分かるものを使う。
  2. 分からなければ、似た命題の過去の見積もり（知見プール）を参考にする。
  3. それでも決まらなければ、桁（100 万・1,000 万・1 億…）だけでよい。幅は1桁分とる。

### 4.2 不確実性の5段階【叩き台】

| 点数 | 呼び方 | 目安 | 知見の状態（参考） |
| --- | --- | --- | --- |
| 5 | 分からない | メカニズムも推測できない。結果の桁も分からない | 知見なし |
| 4 | 推測だけ | メカニズムは推測できるが、数値の根拠がない | 似た知見がない、または適用範囲の外 |
| 3 | 見当はつく | 似た条件の知見・計算があり、桁は分かる。条件の違いで外れるかもしれない | 推定・計算（条件が違う） |
| 2 | ほぼ分かる | 同じ条件の計算・試験の知見がある。外れても小さい | 計算・試験（同じ条件） |
| 1 | 分かっている | 実績で確かめられている。これ以上調べても変わらない | 実績（量産・市場） |

- 不確実性は**人が決める**。システムは、判断の材料として関係する知見（似たリスク・メカニズム・その確からしさと適用範囲）を並べて見せるだけで、点数を自動では決めない。
- 右の列は目安。知見があっても、条件が違うと思えば大きく付けてよい。
- 知見プールが育つほど、同じ種類のリスクの不確実性を小さく見積もれるようになる。そのリスクは優先度が下がり、本当に分かっていないところに工数が向く。

### 4.3 誰が見積もったかを残す

- 5項は**誰が見積もってもよい**。
- 値を入れるたびに、次を記録する（上書きせず、履歴として残す）：

| 記録すること | 例 |
| --- | --- |
| 項目と値（幅） | 感度 0.2／0.3／0.5 |
| 見積もった人 | 山田 |
| 記入した人（違う時） | 田中（代理） |
| 日時 | 2026-10-22 10:12 |
| 根拠 | 「納期遅れ 1 か月で顧客の立ち上げが 1 四半期遅れる」（聞き取り）、関係する知見へのリンク |

- 優先度の一覧では、今の値と見積もった人が見える。見積もりが変わったら、前の値と変えた人も見える。

### 4.4 優先度も幅で出す【叩き台】

4項が幅を持つので、優先度も幅を持つ。システムは次のように計算して見せる。

1. **計算**：各項を幅の中で何千回も選び直して優先度を計算し（モンテカルロ法）、優先度の幅を出す。
   - 低い・最も確からしい・高いは三角分布として扱う【案】。
   - 出すもの：中央値、幅（10%〜90%）。
2. **並べ方**：中央値の大きい順に並べる。幅も棒で見せる。
3. **順位の入れ替わり**：隣のタスクと幅が重なっている時は「順位が入れ替わるかもしれない」と、入れ替わる確率を見せる。
4. **効いている見積もり**：優先度の幅を一番広げている項を示す。
   - その項を確かめると、どちらを先にやるべきかがはっきりする。
   - 「その見積もりを確かめるタスク」（例：顧客に聞く、工数を見積もり直す）を作ってもよい。これも「優先順位を誤るリスク」を減らす活動として扱う。

- 見積もりが確かめられたら、幅を狭めて入れ直す（4.3 の通り、前の値と変えた人も残る）。
- 優先度は、タスクを1つ終えるたびに見直す。新しい知識で、ほかのタスクの見積もり（特に不確実性と感度）が変わるため。

### 4.5 計算の例【叩き台】

命題「顧客価値の最大化」の3つのタスク（数字は架空）。各項は「低い／最も確からしい／高い」。

| タスク | 顧客価値量（億円／年） | 感度 | 寿命（年） | 不確実性 | 検証コスト（万円） |
| --- | --- | --- | --- | --- | --- |
| A：部品の調達リードタイムと供給能力を試算（欲しい時に届くか） | 1.5／2／3 | 0.2／0.3／0.5 | 3／5／7 | 4 | 30／40／60 |
| B：残留振動の対策案を試作で確かめる | 2／3／4 | 0.1／0.2／0.4 | 3／5／7 | 3 | 300／400／800 |
| C：外装色の好みを聞き取る | 0.3／0.5／1 | 0.02／0.05／0.1 | 2／3／5 | 3 | 10／20／30 |

計算の結果（2 万回の計算）：

| 順 | タスク | 優先度の中央値 | 幅（10%〜90%） | 順位の入れ替わり | 幅を一番広げている見積もり |
| --- | --- | --- | --- | --- | --- |
| 1 | A | 3,245 | 2,121〜4,930 | B に抜かれる確率 ほぼ 0% | — |
| 2 | B | 203 | 118〜342 | C に抜かれる確率 35% | 感度 |
| 3 | C | 158 | 83〜293 | — | 感度 |

- A は幅を考えても一番。迷わず実行する。
- B と C は幅が大きく重なり、35% の確率で順位が入れ替わる。どちらも「感度」の見積もりが一番効いている。
  - A を実行している間に、B・C の感度を確かめる（振動が顧客価値にどれだけ効くか、色の好みがどれだけ効くかを聞く）と、次にどちらをやるべきかがはっきりする。

## 5. A3 と知見プール

### 5.1 A3（タスク1つの結果を1枚に）

1つのタスクの結果を A3 1枚にまとめる。少なくとも次を書く。

| 欄 | 中身 |
| --- | --- |
| 命題とリスク | 何の命題の、どのリスクを減らすためのタスクだったか |
| メカニズム（実行前） | リスクが顧客価値に効く因果のつながりの推測 |
| 優先度 | 実行を決めた時の各項の値の幅（見積もった人つき）と、優先度の中央値と幅 |
| やったこと | 方法・条件・前提 |
| 新しい知識 | 分かったこと（数値・曲線・限界・失敗も） |
| 因果関係（実行後） | 確かめられた・否定された因果のつながり。メカニズムの推測がどう変わったか |
| リスクの変化 | 減った・消えた・新しく見つかったリスク |
| 次のタスク | 残ったリスクに対して次にやること |

### 5.2 知見プール

- A3 が貯まる場所。会社の設計ノウハウの本体。
- 次の命題でリスクを挙げる時・メカニズムを推測する時・担当者が不確実性を見積もる時に、ここを引く（判断の材料。値を自動では決めない）。
- 知見プールから引けるもの【案】：
  - リスクの一覧（似た命題で過去に挙がったリスク）
  - メカニズム（因果のつながり。確かめられたもの・否定されたもの）
  - 知識（数値・曲線・限界・失敗）と、その適用範囲・確からしさ

## 6. 中心となるもの（概念モデル）【案】

```
 命題 ──1:多── リスク ──多:多── メカニズム（因果のつながり）
                 │                      ↑ 参考
                 1:多                    │
                 ↓                      │
               タスク（優先度の5項）──実行──→ A3 ──入れる──→ 知見プール
                                              │                │
                                              └── リスクの変化 ─┘（次のリスク・メカニズム・不確実性へ）
```

| もの | 中身 | 一生 |
| --- | --- | --- |
| 命題 | 開発で実現したいこと（例：顧客価値の最大化）。下位の命題に分けてよい | リスクがなくなれば完了 |
| リスク | 命題が失敗する原因になり得ること | 挙がる → 減る → なくなる（または受け入れる） |
| メカニズム | リスクが命題に効く因果のつながり。推測から始まり、タスクで確かめられる | 推測 → 確かめられた／否定された |
| タスク | リスクを減らすための活動。顧客価値量・感度・寿命・不確実性・検証コストと優先度を持つ。各値に見積もりの履歴（誰が・いつ・根拠） | 候補 → 実行中 → 完了 |
| A3 | タスク1つの結果を1枚に | 完了したら知見プールへ |
| 知見プール | A3 の集まり。リスク・メカニズム・知識を引ける | 使われるほど育つ |

## 7. 利用場面【案】

| # | 場面 | 流れ |
| --- | --- | --- |
| UC1 | 命題を立てる | 命題を書くと、知見プールから似た命題のリスクとメカニズムが出てくる |
| UC2 | リスクとメカニズムを書く | リスクを挙げ、顧客価値までの因果のつながりを推測して書く |
| UC3 | タスクを考え、並べる | タスクごとに5項を入れると優先度が出て、大きい順に並ぶ。不確実性を入れる時は、関係する知見が横に出る |
| UC4 | 実行して A3 にまとめる | 結果・因果関係・リスクの変化を A3 1枚に書き、知見プールに入れる |
| UC5 | 見直す | 新しい知識で、残りのリスク・メカニズム・タスクの優先度を直す |
| UC6 | 命題を閉じる | 残ったリスクがないことを確かめる（受け入れたリスクは理由を残す） |
| UC7 | 学ぶ・引く | 製品・部位・現象ごとに、知見プールのメカニズムと知識を読む |

## 8. 成長の測り方【案】

| 指標 | 意味 |
| --- | --- |
| 知見プールの再利用 | A3・メカニズムが、別の命題で何回引かれたか |
| 不確実性の下がり方 | 担当者が見積もった、似たリスクの不確実性が、案件を重ねるごとに下がっているか |
| 優先度の当たり | 優先度の高かったタスクほど、実際にリスクを大きく減らしたか |
| 検証コストあたりのリスクの減り | 同じ工数で、どれだけリスクを減らせたか |
| 後から見つかったリスク | 命題を閉じた後（量産後など）に見つかったリスクの数（減ってほしい） |

## 9. 対象と範囲

- **対象の開発**：要素開発から量産移管前まで。例：電気機械構造物の製品の改良版。
- **使う人**：
  - 設計者：リスク・メカニズム・タスクを書き、A3 にまとめる。
  - 取りまとめ役：命題を立て、優先度と順番を決める。
  - DR の審査者・管理職：リスクの残り方と、判断の根拠を見る。
  - 新しく入った人：知見プールで学ぶ。
- **第1期の範囲【案】**：1つの試験チームで1つの命題を立て、リスクを減らすループを数回まわす。そこで A3 が知見プールに入り、次のタスクの見積もりに使われるところまで。
