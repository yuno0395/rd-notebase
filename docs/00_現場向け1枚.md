# 知見ノートの書き方(現場向け1枚) v0.19

> この Markdown が正本です。共有 vault の直下に置きます。詳しくはマニュアル「チームメンバー 普段の仕事」、仕組みの全体と理由は 00_仕様書.md(まとめ役向け)にあります。
> 作成: 山田 ・ 書き出し: 2026-11-07

開くのは**個人 vault だけ**です。他の人のノートも、同期で個人 vault に届きます。属性欄(先頭の --- で囲まれた所)は、ほとんど手で直さなくて大丈夫です。

## 覚えるキーは4つ

書いた行(か選んだ文字)で押すと、その名前のノートができて、行はリンクに変わります。質問はありません。

| キー | すること | 例 |
| --- | --- | --- |
| Ctrl+K | 物や値の名前(ノード)につなぐ | PA66、保圧、ヒケ量 |
| Ctrl+I | 心配ごと(イシュー)にする | 肉厚部のヒケで外観不良になるおそれ |
| Ctrl+T | 半日以上かかる仕事(タスク)にする | 保圧を変えて試作する |
| Ctrl+U | 案(設計案)にする | B案 ねじ止め式 |

- 新しいノードを作るときと Ctrl+N で作るときは、だれに見せるか(PIP / Internal use only / プロジェクト名)を選びます。人に見せないものは PIP(Esc も PIP)で、`00_PIP/メモ/` に入ります。今のノートから Ctrl+I・T などで作ると、今のノートと同じ範囲になります。
- どこで押しても、つながり先(どの案の心配か、どの心配を減らす仕事か)は今いるノートから自動で入ります。
- キーを忘れたら、本文を右クリックしてメニューから選びます。
- ほかに使うのは Ctrl+S(保存)と Ctrl+L(行をチェックボックス `- [ ]` に)くらいです。

## 1. 書く

- 思いついたことは、今日のデイリーノートの「メモ」か、今やっている仕事のノートに書きます。
- 写真・PDF・Excel は、ノートに貼るかドラッグするだけです。図は Ctrl+D で描きます。
- 5分でできる細かい仕事は Ctrl+L のチェックボックスで十分です。
- 人に見せないメモは、Ctrl+N の一番上「メモ(共有しない)」で作ります。メモや PIP のノートを共有したくなったら、右クリックか上の帯の「共有する」を押します。逆は「共有をやめる」です。

## 2. 心配ごとと案を書く

- 「この案で本当に目標を満たせるか」を脅かす心配を、1行書いて Ctrl+I。インパクトは「未判定」のままでかまいません。金曜に PL が決めます。
- 別のやり方を思いついたら、1行書いて Ctrl+U。案のノートには「この案の中身」と「価値の仮説を実現できるか」の表だけを書きます。採用・不採用は PL が決めます。

## 3. 仕事を進めて終える

- タスクの一番上の「背景」には、減らすイシューとそのリスク、脅かされている設計案、価値の仮説、目的が同期のたびに自動で出ます。なぜこの仕事をするのか迷ったらここを見ます。
- status は **未着手 / 進行中 / 待ち / 完了** の4つから選びます。始めたのに未着手のままでも、同期が 進行中 にします。やめたら 中止(消さない)。
- 同時に進めるのは1人3件まで(待ちは数えません)。
- 終わったら、タスクの「リスクはどう変わったか」に、写真と数値を数行書きます。大きな心配のときは、PL と相談してナレッジにします。
- 誰かに見てもらうときは、属性欄の review_request に名前を書きます(例 `[345678_田中]`)。次の同期で 確認待ち になります。

## 守ること

- 顧客から受け取った図面・仕様書は機密フォルダに置きます。ノートには顧客名や図番を書きません(顧客名を伏せた数値は書いてよい)。
- 共有されないノートは、今日のデイリーノートの先頭に理由と直し方が出ます。わからないことは PL に聞いてください。
