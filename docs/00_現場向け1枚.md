# 知見ノートの書き方(現場向け1枚) v0.13

> この Markdown が正本です。共有 vault の直下に置きます。仕組みの全体と理由は 00_仕様書.md(まとめ役向け)にあります。
> 作成: Yu ・ 書き出し: 2026-10-25 ・ 下書き: https://claude.ai/artifact/5pqwnAkX8wwwpcCx7MoGX1

覚えることは3つだけです。属性欄(先頭の --- で囲まれた所)は手で直さなくて大丈夫です。

**よく使うキー**

| キー | すること |
| --- | --- |
| Ctrl+L | 行をチェックボックス `- [ ]` にする。もう一度押すと完了 |
| Ctrl+K | 選んだ語を `[[ ]]` でつなぐ。ノードがなければその場で作る(質問なし)。何も選ばずに押すと、名前と別名でノードを探せる |
| Ctrl+I / Ctrl+T | 選んだ文字か、カーソルの行の文を、その場でイシュー / タスクにする(質問なし。イシューのインパクトは「未判定」で入り、金曜に決める。イシューはいちばん近いソリューション候補の下に入る) |
| Ctrl+H | 行を価値の仮説にする(parent には目的が入る。仮説の中で押すと、その下の仮説になる) |
| Ctrl+U | 行をソリューションの候補(仮説を実現する案)にする。仮説か目的の中で押すとその下に、ソリューションの中で押すと下の細かい案になる |
| Ctrl+S | 保存する。まだファイルのない `[[ ]]` があれば、名前を右上に出す(ファイルは作らない) |
| Ctrl+Shift+S | 今すぐ共有へ。保存して、すぐ共有 vault へ送る(ふだんは数分ごと)。ノートの上の帯のボタンでもよい |
| Ctrl+D | このノートの図(Excalidraw)を開く。なければ作って、カーソルの位置に引用を入れる |
| Ctrl+J | (準備中)今の仕事が「目的への貢献が一番大きく、自分で進められ、少しチャレンジング」かを確かめる |
| Ctrl+G | 今のノートを中心に K-Plex(つながりの図)を開く |
| Ctrl+Shift+N | K-Plex の中心のノートから、イシュー・タスク・仮説・ソリューションを作る(種類を選んで名前を打つ) |

キーを忘れたら、本文を右クリックしてメニューから選んでもよい。メニューには「ノード・イシュー・タスク・仮説・ソリューション・目的・ナレッジにする」「関係としてつなぐ」「反論としてつなぐ」「図を開く」「チェックボックスにする」「K-Plex で見る」「今すぐ共有へ」がある。`[[ ]]` の上で「関係としてつなぐ」を押すと、そのノートが関係するもの(friend)として属性欄に入る。目的とナレッジはメニューからだけ作る。

## 1. メモを書く

- 思いついたことは、**今日のデイリーノートの「メモ」**か、**今やっている仕事のノート**に書く。inbox にファイルを作らなくてよい。
- 出てきた物や値の名前(PA66、保圧、ヒケ など)は Ctrl+K で `[[ ]]` にする。打つだけでもよい。あとで `[[ ]]` の中にカーソルを置いて Ctrl+K(ノード)や Ctrl+I(イシュー)を押せば、その種類で作れる。ノードの別名は属性欄の aliases に足す。
- 「5分後にやる」ような細かい仕事は Ctrl+L でチェックボックスにする。期日をつけると(`📅 2026-10-24`)、その日のデイリーノートに集まる。
- 写真・図・PDF・Excel・pptx は、ノートに貼るかドラッグするだけ。ファイル名はそのままでよい。どこに置くか迷うファイルだけ `00_inbox/` に置く。
- スマホの写真は、Box アプリで共有の `開発ノート_共有/00_inbox/` に上げ、PC でノートにドラッグする。
- 図は Ctrl+D で描く。枠1つが「1枚」。画像や Excel のグラフは Ctrl+V で貼れる。
- 顧客から受け取った図面・仕様書は、機密フォルダに置く。ノートには顧客名や図番を書かない。顧客名を伏せた数値(例: ある顧客の設備は月2回止まる)は書いてよい。

## 2. イシューを作る(心配なこと、リスク)

順番は「目的 → 価値の仮説 → ソリューションの候補 → イシュー」です。仮説(例: 当日出荷)を置いたら、まず実現する案の候補を Ctrl+U で出し、候補ごとに「本当に仮説を実現できるか」を問います。それを脅かす心配がイシューです。仕事は、候補を磨いて絞ることです。


急ぐときは、行を選んで Ctrl+I。インパクトは「未判定」で入り、金曜にまとめ役が決めます。ゆっくり作るときはボタン「イシュー」を押して、4つの質問に答えます。

| 質問 | 答え方 |
| --- | --- |
| 名前は？ | 「〜のおそれ」で終わる文。例: 肉厚部のヒケで外観不良になるおそれ / スリープ電流が大きく電池が3年もたないおそれ |
| どの案を脅かす？ | 仮説の下にある「ソリューションの候補」(例: 電池3年 → 大容量電池にする)から選ぶ。候補がまだなければ価値の仮説 |
| インパクトは？ | 上から順に はい / いいえ で答える。答えで開発の方向が変わる → **方針**。候補がいくつか消える → **絞込**。解けないと出荷できない → **出荷**。遅れやコスト増になる → **中**。改善になる程度 → **小** |
| すぐできる？ | すぐ: 1週間以内に今の人・設備・予算で試せる / 時間がかかる |

- **迷ったら「出荷」「すぐ」**。
- 作ると、次の同期でノートの最後の「類似・参考ナレッジ」に、他のプロジェクトの似たイシューや使える知見が足されます。着手する前に目を通してください。
- DR や打ち合わせの指摘は、インパクト中以上だけイシューにします。小は議事録に残すだけでよいです。

## 3. タスクを終える

**タスクのノートを作るのは、半日以上かかってリスクを下げる仕事だけ**です。それ以外はチェックボックスで十分です。進めるタスクは1人3件まで。回答待ち・納品待ちのタスクは status を「待ち」にすれば、3件に数えません。迷ったら、今の仕事が目的に一番効くか、まとめ役と確かめます(Ctrl+J は準備中)。

終わったら、インパクトに合わせて「イシューのリスクがどう変わったか」を残します。

| イシューのインパクト | 残すもの | 確認 |
| --- | --- | --- |
| 方針・絞込・出荷 | ナレッジ図(Excalidraw、画面1枚)とナレッジ。わかったことを関係するノードにも書く | もう1人に見てもらう |
| 中 | タスクの「リスクはどう変わったか」欄に、写真と数値を3行 | 自分で読み返す |
| 小 | タスクの「リスクはどう変わったか」欄に1行 | 自分で読み返す |

- もう1人に見てもらうときは、status を「確認待ち」にし、属性欄の review_request に頼む人の名前を書く(例: `[佐藤]`)。頼まれた人はタスク一覧の「確認待ち(確認する人ごと)」で見つけられる。
- 最後にタスクの status を「完了」にする。やめると決めたら「中止」にする(消さない)。
- イシューの status(未対応 / 対策中 / 低減済み / 解消 / 中止)も直す。

## 困ったとき

- 共有されないノートは、今日のデイリーノートの先頭に理由と直し方が出ます。
- 共有したくないノートだけ、属性欄に `visibility: 個人` と書きます。
- わからないことはまとめ役に聞いてください。押し間違えたら、作ってすぐならそのノートを消してかまいません(取り消しのボタンは準備中)。
