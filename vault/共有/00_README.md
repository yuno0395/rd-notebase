# 開発ノート 共有 vault

チームの知見の正本です。はじめにこのファイルを読んでください。

## 読むもの

| ファイル | 読む人 | 中身 |
| --- | --- | --- |
| 00_現場向け1枚.md | 現場の全員 | メモを書く、イシューを作る、タスクを終える、の3つだけ |
| 00_マニュアル/ | 全員(立場ごと) | チームメンバー・PL・システム管理者ごとの「初期設定」と「普段の仕事」。はじめに 00_マニュアルの案内.md |
| 00_仕様書.md | まとめ役 | 仕組み全体とルールの理由 |
| 00_同期プログラム要件.md | 同期プログラムを作る・直す人 | プログラムが守ること |

この3つと `_仕組み/templates/` などの仕組みのファイルは、GitHub のリポジトリ rd-notebase が正本です。ここにあるのは版を出したときの写しなので、ここでは直さないでください。直したいことは金曜の定例で出します(仕様書「仕組みの正本と配布」)。

## フォルダ

| フォルダ | 置くもの |
| --- | --- |
| 00_週報/<名前>/ | visibility が チーム 以上の週報 |
| 00_inbox/ | スマホの写真の受け口(Box アプリで上げ、PC でノートにドラッグする) |
| 共通/02_ノード/ 共通/03_イシュー/ | どのプロジェクトでも使うノードと、横断のイシュー |
| <プロジェクト名>/ | プロジェクト台帳と、01_目的/ 03_イシュー/ 04_タスク/ 05_ナレッジ/ |
| _仕組み/tools/同期プログラム/ | メンバー.csv(名前と6桁の番号)。のちに同期プログラムの保守手順 |
| _仕組み/tools/配布/<版>/ | 版ごとの配布物 |
| _仕組み/templates/ | テンプレートとスクリプト |
| _仕組み/設定/ | 配る Obsidian の設定と導入手順 |
| 99_archive/ | 古くなったもの(削除せずここへ移す) |

## はじめての人

1. `00_マニュアル/01_チームメンバー_初期設定.md` のとおりに準備する(細かい設定の一覧は `_仕組み/設定/導入手順.md`)。
2. `_仕組み/tools/同期プログラム/メンバー.csv` に自分の名前と6桁の番号(社員番号など、ほかの人と重ならない数字)を1行足す。辞めた人の番号は使わない。id の後ろ4文字は、この番号を36進数にしたもの(229999 → 4XGV)。
3. 同期プログラムができるまでは、ノートはこの vault に直接書く(仕様書「E. 同期プログラムができるまでの仮運用」)。
