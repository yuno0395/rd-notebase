# 導入手順

配布物に入っている設定と、手で選ぶ設定です。上から順に行います。✔ は配布物の設定に入っているもの、☐ は手で選ぶものです。

## 1. vault を開く

| vault | 開き方 |
| --- | --- |
| 個人 | 個人フォルダを Obsidian で開く。設定(`.obsidian/`)は入っている |
| 共有 | 共有フォルダを開き、☐ 設定 → ファイルとリンク →「設定フォルダを上書き」を `.obsidian-<自分の6桁の番号>_<PCの記号>`(例: `.obsidian-229999_aa11234567`。PC ごとに違う記号)にする。Obsidian を開き直し、この `_仕組み/設定/.obsidian/` の中身をその設定フォルダにコピーする。人ごとに設定が分かれ、共有クラウドフォルダで競合しない |
| 機密 | 共有と同じ。中身は機密フォルダの `_仕組み/設定/.obsidian/` から |

個人 vault では、`_仕組み/個人設定.md` の name と number(6桁の数字)を最初に書きます。id の後ろ4文字は、この番号を36進数にしたものです(229999 → 4XGV)。共有・機密の vault では、設定フォルダの名前(`.obsidian-<6桁の番号>_<PCの記号>`)の先頭の番号を使います。個人設定.md の number と同じ番号にしてください。

## 2. Obsidian の設定

- ✔ ファイルとリンク: Wikiリンクを使う、新しいリンクの形式は「最短パス」、ファイル名変更時にリンクを更新
- ✔ 削除したファイル: Obsidian のゴミ箱(.trash)
- ✔ 新しいノートの場所: 個人は 02_ノード/、共有は 共通/02_ノード/、機密は 06_事実/(まだない `[[水]]` をクリックしたときのため)
- ✔ コアプラグイン: Bases・検索・バックリンク・グラフをオン。デイリーノート・テンプレート・Canvas・固有ノート作成はオフ(準備の bat・プラグインを入れる.bat が合わせる。ほかのコアプラグインは各自のまま)

## 3. コミュニティプラグイン

☐ 設定 → コミュニティプラグイン → 制限モードをオフにし、`community-plugins.json` に載っているものを「閲覧」から入れて有効にする。

| プラグイン | 設定 |
| --- | --- |
| Templater | ✔ テンプレートは `_仕組み/templates`、スクリプトは `_仕組み/templates/_scripts`。✔ フォルダ名で 目的・ノード・イシュー・タスク・ナレッジ・事実 のテンプレートが入る規則(File regex templates)。☐ 「Trigger Templater on new file creation」を PC ごとに手でオンにする(安全のため設定ファイルでは配れない。オフのままだとノートの名前が id つきに変わらない)。☐ 1回目に「この vault のスクリプトを信頼するか」と聞かれたら、はい |
| Periodic Notes(個人だけ) | ✔ デイリーは 00_日誌/デイリー/、名前 YYYY-MM-DD、テンプレート デイリー。✔ 週報は 00_日誌/週報/、名前 GGGG-[W]WW、テンプレート 週報 |
| Day Planner(個人だけ) | 入れて有効にするだけ。Periodic Notes のデイリーノートを自動で読む(コアの「デイリーノート」はオフのまま)。確かめ方は 01_チームメンバー_初期設定 の「タイムライン(Day Planner)」 |
| Tasks | 既定のまま |
| QuickAdd | ✔ Ctrl+N の「新しいノート」と種類ごとのボタン(下の 4)。入れて有効にするだけ |
| Excalidraw | ✔(配る設定に入っている)Saving → 「Compress Excalidraw JSON in Markdown」をオフ(図の中身を同期プログラムと Git が読めるように)。Embedding … and Exporting → Export Settings → 「Auto-export SVG」をオン。Basic → 「Excalidraw template file or folder」に `_仕組み/templates/図.excalidraw.md`。手順は 01_チームメンバー_初期設定 の「図(Excalidraw)」 |
| Custom Attachment Location | ✔(配る設定に入っている)貼ったファイルを vault の中の `_仕組み/attachments/<ノートの id>/`(日誌は `日誌/<日付>/`、図に貼った画像は図と同じフォルダ)に元の名前で入れる。設定 → Custom Attachment Location で「Follow Obsidian attachment location」をオフ、「Custom tokens」に `attachDir` の決まり(マニュアルの手順 3)、「Location for new attachments」に `_仕組み/attachments/{{attachDir}}`、「Generated attachment file name」に `{{originalAttachmentFileName}}` を貼る(今の版は `${…}` ではなく `{{…}}` の書き方)。設定 → ファイルとリンク →「新しいリンクの形式」は「Vault フォルダからの絶対パス」。手順は 00_マニュアル の 01_チームメンバー_初期設定 の「貼ったファイルの置き場所」 |
| Advanced Rename and Delete Handler | 既定のまま(Custom Attachment Location に必要) |
| K-Plex(個人・共有) | ✔ 子の属性名に `parts` を足してある(ほかは既定のまま。すでに K-Plex を使っていた PC では、設定 → K-Plex の子(Children)の欄に `parts` を手で足す)。`parent`(上)・`friend`(左)・`previous`(左)・`challenger`(右)は既定の名前に入っていて、大文字小文字は区別しない。個人 vault では `90_共有/` に配られた他の人のノートもつながって見える。✔ テーマ「開発ノート」: カードの色を priority で変え(1 赤・2 橙・3 黄・4 灰)、Graph Lens「終わったものを薄く」で解消・中止・不採用・外れたを灰色にする(すでに K-Plex を使っていた PC では、設定 → K-Plex の Node styles で priority を選んで色を決め、フィルターとレンズでレンズを作る)。☐ K-Plex の中でノートを作ったり、中心のノートの編集欄(Editor node)で書いたりしない |
| Linter | ☐ General → 「Lint on save」がオフか見る(入れたばかりならオフ。属性欄のコメントを消さないため)。手順は 01_チームメンバー_初期設定 の「書式の整え(Linter)」 |
| Iconic | ☐ 当面は既定のまま。type ごとのアイコンはあとで決める |
| Omnisearch | 既定のまま |
| Front Matter Title(個人・共有) | ✔ 見出し・タブ・左の一覧・検索・グラフ・リンクの候補などに、ファイル名の代わりに aliases の最初の名前を出す(id が見えなくなる)。ファイルとリンクは書き換えない。入れて有効にするだけ |
| Commander(個人・共有) | ✔ 本文を右クリックしたときのメニューに「ノード・イシュー・タスク・仮説・設計案・目的・ナレッジにする」「関係としてつなぐ」「反論としてつなぐ」「図を開く」「チェックボックスにする」「K-Plex で見る」が入る。入れて有効にするだけ |

## 4. Ctrl+N で新しいノート

✔ Ctrl+N を押すと種類の一覧が出る(QuickAdd の「新しいノート」)。種類を選んで名前を打つと、決まったフォルダにテンプレート入りのノートができ、名前は `id_名前` になる。Obsidian 標準の Ctrl+N(無題のノート)は外してある。

| 種類 | 個人 vault | 共有 vault(仮運用) |
| --- | --- | --- |
| 目的・価値の仮説 | 01_目的/ | 作るときにフォルダを選ぶ(「目的」と打つと絞れる) |
| 設計案 | 01_設計案/ | 作るときにフォルダを選ぶ(「設計案」と打つと絞れる) |
| ノード | 02_ノード/ | 共通/02_ノード/ |
| イシュー | 03_イシュー/ | 作るときに選ぶ(<プロジェクト名>/03_イシュー/ か 共通/03_イシュー/) |
| タスク・議事録・実験・試作記録 | 04_タスク/ | 作るときに選ぶ |
| ナレッジ | 05_ナレッジ/ | 作るときに選ぶ |
| プロジェクト | ― | 作るときに選ぶ(新しいフォルダの名前も打てる) |
| 事実(機密 vault) | ― | 06_事実/ |

- 名前を打つ前なら Esc で何も作らずにやめられる。
- 手で新しいファイルを作っても、フォルダ名でテンプレートが入る(Templater)。そのときは名前が「無題」になるので、あとで直す。

## 5. ショートカットキー

同じ動きは、本文を右クリックしたメニューからも選べる(Commander)。`[[ ]]` の上で右クリックすると、そのリンクが対象になる。

- Ctrl+L(行を `- [ ]` にする)は Obsidian に最初から入っている。
- ✔ Ctrl+D: 書いている途中で押すと、このノートの図ができて右に開き、カーソルの位置に1枚目のフレームの引用が入る。2回目からは図を開くだけ。2枚目からは Excalidraw でフレームを選び「フレームへのリンクをコピー」で貼る。
- ✔ Ctrl+K: 選んだ語をノードにつなぐ(なければ作る)。何も選ばずに押すと、名前と別名で探す検索窓が出る。標準の Ctrl+K(Markdown リンク)は外してある。
- ✔ Ctrl+S: ふつうに保存し、まだファイルのない `[[ ]]` があれば名前を右上に出す(ファイルは作らない)。標準の保存の Ctrl+S は外してあるが、保存そのものは同じコマンドを呼ぶ。
- ✔ Ctrl+G: 今のノートを中心に K-Plex を開く。標準の Ctrl+G(グラフ表示)は外してある。
- ✔ 右クリックの「関係としてつなぐ」「反論としてつなぐ」: `[[ ]]` の上で使うと、そのリンク先を今のノートの friend / challenger に足す。
- ✔ Ctrl+I / Ctrl+T / Ctrl+H / Ctrl+U: 選んだ文字か、カーソルの行の文を、イシュー / タスク / 仮説(どのノートでも。仮説の中なら下の仮説) / 設計案の候補(仮説・目的の中ならその下、設計案の中なら下の細かい案)にする。標準の Ctrl+I(斜体)・Ctrl+T(新しいタブ)・Ctrl+H(検索と置換)は外してある。目的とナレッジは右クリックのメニューから作る。
- ✔ Ctrl+Shift+N: K-Plex の中心のノートから、イシュー・タスク・仮説・設計案を作る(QuickAdd の「K-Plex の中心から作る」。スクリプトは `_仕組み/templates/_quickadd/K-Plexの中心から作る.js`)。K-Plex を開いていなければ、今のノートから作る。
- ✔ Ctrl+J: 今のタスク(デイリーのタイムラインで今の時刻の行、なければ開いているタスク)が、目的への貢献が一番大きいか・自分で実行できるか・少しチャレンジングかを ○ × で出す。× があれば代わりの候補を3つ出す。右クリックのメニューにもある。

## 6. 確かめること

導入したら、次を確かめて金曜の定例で報告する。

- [ ] Ctrl+N → イシュー → 名前を打つと、ファイル名が `0R…001_名前.md` になり、属性欄に id が入る
- [ ] 共通/02_ノード/ に手で新しいノートを作っても、テンプレートと id が入る
- [ ] 画像を貼ると `_仕組み/attachments/<id>/` に元の名前で入る
- [ ] Ctrl+L で、何もない行に `- [ ]` ができる
- [ ] 00_イシュー一覧.base が priority 順に並ぶ
- [ ] 語を選んで Ctrl+K を押すと `[[id_語|語]]` になり、02_ノード にノードができる(開かない)。何も選ばずに押すと検索窓が出る
- [ ] イシューのノートで `- [ ] 保圧を上げる 📅 2026-10-31` の行にカーソルを置いて Ctrl+T を押すと、`- [ ] [[id_保圧を上げる|保圧を上げる]] 📅 2026-10-31` になり、04_タスク のタスクの parent にそのイシューが入る
- [ ] タスクのノートで右クリック →「ナレッジにする」で、05_ナレッジ のナレッジの risk_reduction にイシューが入る
- [ ] 新しいノードの属性欄に aliases があり、正式名が入っている
- [ ] `[[まだない名前]]` を書いて Ctrl+S を押すと、右上に「ファイルのないリンク: まだない名前」と出る
- [ ] ノートで Ctrl+D を押すと、16:9 の枠が1つある図が右に開き、カーソルの位置に引用が入る
- [ ] ノートを開いて Ctrl+G を押すと、K-Plex がそのノートを中心に開く
- [ ] parts を書いたノードを K-Plex で見ると、parts のノードが下に並ぶ
- [ ] `[[ ]]` の上で右クリック →「反論としてつなぐ」で、属性欄に `challenger: ["[[id_名前|名前]]"]` が入り、K-Plex の右に出る
- [ ] 目的のノートで行に Ctrl+U を押すと、成果物候補が 01_設計案/ にでき、parent に目的が入る
- [ ] 成果物候補のノートで行に Ctrl+U を押すと、部分の案ができ、parent にその候補が入る
- [ ] 仮説のノートで行に Ctrl+U を押すと、parent に目的、価値仮説にその仮説が入った設計案ができる
- [ ] 設計案のノートで Ctrl+I を押すと、新しいイシューの 脅かす にその設計案が入り、K-Plex で設計案を中心にすると右に出る
- [ ] 設計案で価値の仮説の `[[ ]]` の上で右クリック →「関係としてつなぐ」で、属性 価値仮説 に入り、K-Plex で左に出る
- [ ] タスクで Ctrl+I を押すと、新しいイシューの 脅かす に元のイシューの設計案、previous にそのタスク、generation に 2 が入る
- [ ] priority の空のイシューも、00_イシュー一覧.base の priority の列に数字が出て、その順に並ぶ
- [ ] K-Plex で、イシューやタスクが id のつかない名前で出る。priority 1 のイシューが赤く、解消したイシューが灰色で出る
- [ ] タスクの属性欄に review_request があり、確認待ちにして名前を書くと、00_タスク一覧.base の「確認待ち(確認する人ごと)」に出る
- [ ] Ctrl+N → DR 議事録 で、属性欄に kind: DR、本文に「解像度の判定」「絞り込み」の欄がある
- [ ] 00_イシュー一覧.base の「DR 用」ビューで、impact 大のイシューが resolution の段階ごとにまとまる
- [ ] 仮説のノートで行に Ctrl+H を押すと、新しい仮説の parent に元の仮説が入る
- [ ] K-Plex でイシューを中心にして Ctrl+Shift+N →「タスク」→ 名前 で、parent にそのイシューが入ったタスクができ、K-Plex の下に出る
- [ ] プロジェクトのノート(台帳)を開くと、そのプロジェクトの解消・中止でないイシューが priority 順に出る
- [ ] ノートの見出し・タブ・左の一覧に id が出ず、名前だけが出る(Front Matter Title)
- [ ] 00_設計案一覧.base と 00_ノード一覧.base が開ける(個人 vault にもある)
